## 1. 設問から読む

本文を先に全部読むと、設問を見たときに内容を忘れていて、もう一度読み直すことになります。**設問を先に読み、何を探すかを決めてから本文を読む** のが基本です。

## 2. マーキングのルール

紙の場合は色ペン、CBTの場合はメモ用紙に段落番号と記号でメモします。ルールを決めておくと、読み返す時間が減ります。

| 記号 | 何に付けるか | 理由 |
|---|---|---|
| □（四角） | 会社名・システム名・登場人物 | 誰が何をしたかを混同しない |
| ＿（下線） | 「問題」「課題」「懸念」「〜できない」「〜のおそれ」 | 対策・理由を問う設問の根拠になる |
| ◎ | 「〜する方針」「〜したい」「要件」 | 解答の方向性（条件）になる |
| 数字に○ | 金額・件数・時間・率 | 計算問題で使う。単位も一緒に囲む |
| 矢印 → | 処理の流れ、データの流れ | ネットワーク・DB・組込みの設問で使う |

## 3. 下線・空欄・表の読み方

- **下線部の設問**：答えは、ほとんどの場合 **下線部の前後3行以内** にある。下線部の段落を丁寧に読む。
- **空欄の設問**：空欄の前後の文の「主語」と「述語」から、入る字句の品詞と種類を決める。同じ空欄が別の場所にもあれば、両方に当てはまるものを選ぶ。
- **表の設問**：表の列見出しを先に読み、行ごとに何が違うかを比べる。空欄のある行と、空欄のない行の違いがヒントになる。
- **図（構成図）**：機器とアドレス、通信の向きを書き込みながら読む。

## 4. 条件を拾う

設問の文には、答えの範囲を絞る **条件** が含まれています。条件を無視した解答は、内容が正しくても得点になりません。

| 条件の例 | 意味 |
|---|---|
| 「本文中の字句を用いて」 | 本文の言葉をそのまま使う。言い換えない |
| 「〇〇の観点から」「費用面の」 | その観点だけで答える |
| 「〜を踏まえて」 | 指定された事実を必ず根拠に含める |
| 「具体的に」 | 用語だけでなく、何を・どうするかまで書く |
| 「二つ答えよ」 | 2つの異なる要素を書く（同じ内容の言い換えは1つと数えられる） |
| 「〇〇以外で」 | 本文で既に挙がっている対策は書かない |

:::trap 採点講評で毎年指摘されていること
「設問で何を問われているかを正しく理解した上で解答してほしい」――分野を問わず、最も多い指摘です。設問文の **最後の一文**（「理由を述べよ」「対策を述べよ」）と **条件** に、必ず印を付けてから解き始めましょう。
:::
