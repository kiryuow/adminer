## 出題テーマ（令和2〜7年度）

内部不正対策 ／ 権威DNSサーバへの攻撃 ／ 物理的セキュリティ ／ 通販サイトの再発防止策 ／ マルウェアの早期発見と活動抑止 ／ インシデント対応と社員教育 ／ PPAPとS/MIME ／ ゼロトラストへの移行 ／ ペネトレーションテストとパスワードの安全な管理 ／ サプライチェーン攻撃（R7春・R7秋）

:::point 毎回同じ流れで出る
「①何が起きたか（攻撃の手口）→ ②なぜ防げなかったか（脆弱性）→ ③技術的にどう防ぐか → ④運用・教育でどう防ぐか」。本文を読むときは、この4つに印を付け分けると設問とすぐ結び付きます。

## 必須知識チェックリスト

<div class="ck" markdown="1">

- CIA（機密性・完全性・可用性）と、真正性・責任追跡性・否認防止を区別して説明できる
- 共通鍵と公開鍵の違い、ハイブリッド暗号、鍵の数（n(n−1)/2 と 2n）を説明できる
- 暗号化とデジタル署名で「誰の」「どちらの」鍵を使うかを言える
- ハッシュ関数の性質（一方向性・衝突発見困難性）と、ソルト・ストレッチングの目的を言える
- 証明書の検証項目（発行者の署名、有効期限、失効していないか＝CRL/OCSP、ホスト名）を言える
- SQLインジェクション・XSS・CSRF・ディレクトリトラバーサルとその対策を対応付けられる
- ファイアウォールのルール（送信元・宛先・ポート・許可/拒否、上から順に評価）を読み書きできる
- DMZ、WAF、IDS/IPS、プロキシ、VPN（IPsec/TLS）、EDR、SIEM の役割を一言で言える
- SPF・DKIM・DMARC、S/MIME、PPAPの問題点を説明できる
- パスワードリスト攻撃、リバースブルートフォース攻撃、多要素認証、リスクベース認証を説明できる
- インシデント対応の流れ（検知→封じ込め→根絶→復旧→再発防止）と、初動で「ネットワークから切り離す」理由を言える
- ゼロトラストの考え方と、IDaaS・SWG・CASB・MDM・EDR の役割を言える
- サプライチェーン攻撃（取引先経由、ソフトウェア更新経由）と SBOM の役割を言える

</div>

## 頻出設問と答え方

| 設問の例 | 答え方の型 |
|---|---|
| 「この攻撃の名称を答えよ」 | 正式な用語で（例：パスワードリスト攻撃） |
| 「この対策で防げる理由を答えよ」 | 「（攻撃者が）〜できなくなるため」「〜が検知できるため」 |
| 「下線の設定のままだと何が起きるか」 | 「〜から〜への通信が許可されてしまい、〜されるおそれがある」 |
| 「ファイアウォールのルールの空欄」 | 送信元・宛先・サービス（ポート）・動作。最小限の許可にする |
| 「初動として実施すべきこと」 | 「感染した PC を LAN から切り離す」（理由：感染拡大と外部への情報流出を防ぐため） |
| 「教育で伝えるべき内容」 | 本文の事故の原因（不審メールの添付ファイルを開いた等）に対応させる |

## 採点講評からの注意点

- **基礎用語の取り違え**：「情報セキュリティの3要素ではない誤った解答が散見された」（R6秋）。CIA の3つは確実に。
- **攻撃名の理解不足**：「リバースブルートフォース攻撃の理解が不十分と思われる解答が散見された」（R7春）。似た攻撃名を区別する。
- **本文の動作から推論する**：マルウェアの動作説明から、通信が業務ではなく侵入後の活動であると導く問題（R4秋）。本文の「動作内容」を根拠にする。
- **用途ごとの特性**：ハッシュ値は改ざん検知など他の用途にも使われ、用途ごとに必要な特性が違う（R6秋）。
- **最小限の原則**：不要なサービスは「最低限必要なものを除き停止する」（R4春）。ルールの設問も同じ発想で。

## ミニ演習（目安12分）

<div class="case" markdown="1">
<div class="ch">事例：Ａ社の通販サイト</div>

Ａ社は自社の通販サイトを運営している。会員のパスワードは、データベースに **SHA-256 のハッシュ値** として保存している（ソルトは使っていない）。ある日、サイト管理者が、海外の多数の IP アドレスから、**多数の会員IDに対して少数回ずつ** ログインが試行され、一部の会員アカウントにログインが成功していることに気付いた。調査の結果、ログインに成功した会員は、**他社のサービスと同じ ID・パスワードを使っていた** ことが分かった。Ａ社は対策として、次の2点を検討している。

(1) パスワードをハッシュ化して保存する方式を見直す。
(2) 会員がログインする際の認証方式を強化する。

</div>

<div class="q" markdown="1"><div class="qh">設問1</div>本文の攻撃の名称を答えよ。</div>
<div class="q" markdown="1"><div class="qh">設問2</div>対策(1)について、ソルトを付加してハッシュ化すると、どのような攻撃に対して効果があるか。また、その理由を30字以内で述べよ。</div>
<div class="q" markdown="1"><div class="qh">設問3</div>対策(2)として有効な認証方式を一つ挙げ、本文の攻撃を防げる理由を35字以内で述べよ。</div>

<div class="write"></div>

<div class="ans" markdown="1"><div class="ah">解答例と解説</div>

**設問1**：パスワードリスト攻撃
→ 他社から漏えいした ID とパスワードの組を使う攻撃。「他社のサービスと同じ ID・パスワード」が根拠。多数の ID に少数回ずつ試すのは、アカウントロックを避けるため。

**設問2**：レインボーテーブル攻撃。理由例「同じパスワードでも会員ごとに異なるハッシュ値になるため」（26字）
→ ソルトは利用者ごとに異なるランダムな値。事前に計算したハッシュ値の表で逆引きできなくなる。さらにストレッチング（ハッシュの繰返し）で総当たりにかかる時間を増やせる。

**設問3**：多要素認証（例：パスワードに加え、会員のスマートフォンに送るワンタイムパスワード）。理由例「漏えいしたパスワードだけでは、会員が持つ端末の確認を通過できないため」（34字）
→ 本文の攻撃は「パスワードが知られている」ことが原因なので、パスワード以外の要素（所持・生体）を加える対策が正対する。

</div>
