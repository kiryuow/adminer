## 頻出設問と答え方

| 設問の例 | 解き方 |
|---|---|
| 「E-R図の空欄にリレーションシップを記入」 | 「1つの A に対して B は複数あるか」「1つの B に対して A は複数あるか」を本文から1つずつ確認 |
| 「SQL文の空欄」 | 求める結果の列（SELECT）→ 表と結合条件（FROM）→ 行の条件（WHERE）→ まとめる単位（GROUP BY）の順に考える |
| 「この表の問題点」 | 「〜を変更すると複数行を更新する必要があり、不整合が生じるおそれがある」 |
| 「同時に更新したときの不具合」 | ロストアップデートなど。対策は「行を読み込む時点で専有ロックを取得する」など |

## 採点講評からの注意点

- **カーディナリティを丁寧に**：「情報端末と契約の関係を1対1とする解答が散見された。関連のカーディナリティを正しく捉えることは概念設計で重要」（R4秋）。
- **条件の記述漏れ**：「列名の指定は正しいが、最小値を指定する記述がない解答が散見された」（R2）。
- **構文を正確に**：「結合は基本的なデータ操作の一つなので構文を理解してほしい」（R3春）、「“WINDOW”と誤って解答した受験者が散見された」（R5秋：正しくは OVER など）。
- **要件とデータを照合**：「業務部門の要件に対して必要なデータが不足していることは現実によくある問題なので、データソースを注意深く精査してほしい」（R3春）。

## ミニ演習（目安12分）

<div class="case" markdown="1">
<div class="ch">事例：Ｅ社の研修受講管理</div>

表の構造（下線は主キー、破線の下線は外部キー）
社員（<u>社員番号</u>, 氏名, 部署コード）
研修（<u>研修コード</u>, 研修名, 定員）
受講（<u>社員番号</u>, <u>研修コード</u>, 受講日, 評価点）　※社員番号・研修コードはそれぞれ外部キー

業務ルール：1人の社員は複数の研修を受講できる。1つの研修は複数の社員が受講できる。

</div>

<div class="q" markdown="1"><div class="qh">設問1</div>「社員」と「研修」の関係の多重度と、それを「受講」表でどのように実現しているかを30字以内で述べよ。</div>
<div class="q" markdown="1"><div class="qh">設問2</div>研修ごとに受講者数と平均評価点を求め、受講者数が10人以上の研修だけを表示する。空欄 a・b を埋めよ。</div>

```
SELECT 研修コード, COUNT(*) AS 受講者数, AVG(評価点) AS 平均点
  FROM 受講
 [ a ] 研修コード
 [ b ] COUNT(*) >= 10
```

<div class="q" markdown="1"><div class="qh">設問3</div>受講が1件もない研修も含めて、すべての研修の研修名と受講者数を表示したい。このとき使う結合の種類を答えよ。</div>

<div class="write"></div>

<div class="ans" markdown="1"><div class="ah">解答例と解説</div>

**設問1**：多対多。解答例「両方の主キーを組み合わせた受講表で1対多を二つに分解している」（30字）
→ 多対多は連関エンティティ（受講）で、社員1対多受講、研修1対多受講に分解する。

**設問2**：a ＝ GROUP BY、b ＝ HAVING
→ 集約関数の結果で絞り込むので WHERE ではなく HAVING。

**設問3**：左外部結合（研修 LEFT OUTER JOIN 受講）
→ 内部結合では受講のない研修が消える。左外部結合で研修を全件残し、COUNT(受講.社員番号) とすると受講がない研修は 0 になる（COUNT(*) だと NULL の行も1と数える点に注意）。

</div>
