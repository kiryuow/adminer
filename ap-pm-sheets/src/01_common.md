午後の設問は、分野が違っても「聞き方」はいくつかの型に分類できます。型ごとに答え方を決めておけば、初めて見る事例でも手が止まりません。

## 1. 記述の大原則

<div class="fig"><div class="fig-t">記述の4原則<small>採点講評で毎年のように指摘されるポイント</small></div><div class="fig-b"><div class="cards" style="--n:4">
<div class="card c1"><b>①問いに正対する</b>「理由」を聞かれたら理由、「対策」なら対策を書く。聞かれていないことは書かない</div>
<div class="card c2"><b>②根拠は本文から</b>一般論ではなく、本文に書かれた事実（下線部の前後、表、図）を根拠にする</div>
<div class="card c4"><b>③本文の言葉を使う</b>本文中の用語をそのまま使う。言い換えると意味がずれ、減点されやすい</div>
<div class="card c3"><b>④具体的に書く</b>「セキュリティが低下する」ではなく、「何が・どうなるか」まで書く</div>
</div></div></div>

:::trap 採点講評で繰り返し指摘されていること（全分野共通）
- 「設問で問われていることを正しく理解した上で解答してほしい」── 問いの条件（「費用面の」「〇〇の観点から」）を無視した解答
- 「単に“アクセス権”としか記述していない解答が多かった」── 用語だけを挙げ、具体的な内容がない解答
- 「本文で説明していない用語や機能の解答が散見された」── 本文にない知識で答えてしまう
- 「数値が若干異なる解答が散見された」── 計算の条件の読み落とし、単位の換算ミス
:::

## 2. 設問の型と答え方の型

<div class="tpl" markdown="1">

| 設問の型 | 答え方の型（文末） | 解答例のフレーズ |
|---|---|---|
| 理由・目的を問う | 「〜ため」「〜するため」 | 「感染した PC から他の PC へ感染が広がるのを防ぐため」 |
| 問題点・リスクを問う | 「〜という問題がある」「〜のおそれがある」 | 「同じ経路でパスワードを送るため、盗聴されると内容が漏えいするおそれがある」 |
| 対策・施策を問う | 「〜する」（主語と対象を明確に） | 「管理者アカウントに多要素認証を設定する」 |
| 効果を問う | 「〜できる」「〜が減る」 | 「障害時に待機系へ自動で切り替わり、停止時間を短縮できる」 |
| 何を確認すべきか（監査） | 「〜の記録を確認し、〜が行われているかを確かめる」 | 「権限見直しの実施記録を閲覧し、四半期ごとに承認されているかを確かめる」 |
| 用語・名称を問う | 用語だけを正確に | 「ファストトラッキング」 |
| 本文から抜き出す | 指定字数で、本文の字句をそのまま | （「本文中の字句を用いて」という指示に注意） |
| 計算 | 数値（指定された単位・桁数で） | 「12.5（小数第2位を四捨五入）」 |
| 穴埋め（字句・プログラム） | 前後の文・変数の意味から逆算 | 「mid＋1」 |

</div>

### 字数の調整

- 指定字数の **8割以上** を目安に書く（30字以内なら24〜30字）。
- 字数が足りないとき：「何が」「何を」「どうなる」のうち抜けている要素を足す。
- 字数が多すぎるとき：修飾語を削る。2つの要素を書いているなら、問いの核心の1つに絞る。
- 「〜の観点から」「本文中の字句を用いて」などの **条件は下線を引いて** から書き始める。

## 3. 時間配分（150分・5問）

| 時間 | やること |
|---|---|
| 0〜5分 | 問2〜問11をざっと見て、選択する4問と順番を決める（得意な分野から） |
| 5〜35分 | 問1（必須）を解く |
| 35〜140分 | 選択問題4問を1問25〜26分で解く。30分を超えたら次へ |
| 140〜150分 | 空欄を埋める、選択の操作を確認する、計算の単位を見直す |

:::how 1問30分の使い方
**①設問を先に読む（2分）**：何を問われているか、字数と条件を確認。**②本文を読む（10分）**：設問に関係する箇所に印。**③設問を解く（15分）**：解ける設問から。**④見直し（3分）**：文末が問いの形に合っているか。
:::

:::note 迷ったときの定番の組合せ
