**OS（オペレーティングシステム）** は、ハードウェアとアプリケーションの間に立って、CPU・メモリ・ファイルなどの資源を管理する基本ソフトウェアです。複数のプログラムを同時に動かしているように見せたり、メモリが足りなくても大きなプログラムを動かしたりできるのは、OSの働きです。この章の内容は、午前に加えて午後の問7（組込みシステム開発）でも重要です。

## 1. タスク（プロセス）管理

### タスクとは

**タスク（プロセス）** とは、OSから見た「実行中のプログラム」の単位です。OSは複数のタスクに CPU を少しずつ順番に割り当てることで、同時に動いているように見せます（**マルチタスク**）。

### スケジューリング方式

どのタスクに次に CPU を割り当てるかを決める方式です。

| 方式 | 内容 |
|---|---|
| **到着順（FCFS）** | 先に到着したタスクから順に実行する |
| **処理時間順（SPT）** | 処理時間が **短い** タスクから実行する。平均待ち時間が最小になる |
| **優先度順** | 優先度の高いタスクから実行する。低優先度のタスクがいつまでも実行されない「飢餓状態」に注意 |
| **ラウンドロビン** | 一定時間（**タイムクウォンタム**）ずつ順番に CPU を割り当て、時間切れになったら列の最後に戻す |
| **プリエンプティブ** | 実行中のタスクから強制的に CPU を奪える（横取りあり）方式 |

:::calc 処理時間順スケジューリングのターンアラウンドタイム
| ジョブ | 到着時刻 | 処理時間 |
|---|---|---|
| A | 0 | 3 |
| B | 1 | 4 |
| C | 2 | 1 |
多重度1、横取りなしの処理時間順。時刻0では A しかないので A を実行（0〜3）。時刻3の時点で B と C が待っており、短い C を先に実行（3〜4）、次に B（4〜8）。
Bのターンアラウンドタイム ＝ 終了時刻 8 − 到着時刻 1 ＝ **7**
**「その時点で到着済みのジョブの中から選ぶ」** のがポイントです。
:::

:::exam R7秋 午前問15
5つのジョブを処理時間順で実行したときの、あるジョブのターンアラウンドタイムを求める問題。上の計算例と同じく、時刻を1つずつ進めながら「到着済みで最も短いジョブ」を選んでいけば解けます。
:::

### スレッドとリアルタイムOS

- **スレッド**：1つのタスクの中で、さらに並行して動く処理の単位。同じタスク内のスレッドはメモリを共有するので、切替えが軽い。
- **スレッドセーフ**：複数のスレッドから同時に（並列に）呼び出されても、問題が生じない（正しく動く）こと。
- **リアルタイムOS（RTOS）**：決められた時間内に必ず処理を終えること（**リアルタイム性**）を重視したOS。組込み機器で使われる。優先度に基づく **イベントドリブン型プリエンプティブ** スケジューリングを使うことが多い。

:::exam R7秋 午前問17
スレッドセーフの説明を選ぶ問題。「アプリケーションを複数のスレッドで並列に実行しても、問題が生じない」が正解です。
:::

## 2. 排他制御・セマフォ・デッドロック

### 排他制御とは

複数のタスクが同じ資源（データ、プリンタなど）を同時に書き換えると、データが壊れることがあります。これを防ぐため、**ある資源を1つのタスクが使っている間は、他のタスクに使わせない** ようにすることを **排他制御** といいます。

### セマフォ

**セマフォ** は、排他制御や同期を実現する代表的な仕組みです。資源の空き数を表すカウンタを持ち、次の2つの操作で制御します。

- **P操作**：資源を使う前に行う。カウンタを1減らす。0なら（空きがなければ）待ち状態になる。
- **V操作**：資源を使い終わったら行う。カウンタを1増やし、待っているタスクがあれば起こす。
- カウンタの初期値を1にすると、同時に1つのタスクしか使えない（**バイナリセマフォ**・ミューテックス）。

:::exam R7秋 午前問16
1つの I²C バスにつながった2つのセンサーの値を読む2つのタスクを、排他的に制御したい。リアルタイム OS のどの機能を使うか？ → **セマフォ**。「排他的に制御」という言葉が出たら、セマフォ（またはミューテックス）を思い出しましょう。
:::

### デッドロック

**デッドロック** とは、2つ以上のタスクが、互いに相手の持っている資源の解放を待ち合って、**どちらも永久に先に進めなくなる** 状態です。

## 3. 記憶管理

### 実記憶管理（主記憶の割当て）

主記憶の空き領域にプログラムを割り当てる方式として、次の3つがよく出ます。

| 方式 | 割当て方 | 特徴 |
|---|---|---|
| **ファーストフィット** | 先頭から探し、**最初に見つかった** 十分な大きさの空き領域に割り当てる | 探索が速い |
| **ベストフィット** | 要求された大きさを満たす **最小の** 空き領域に割り当てる | 大きな空き領域が残るが、**小さな空き領域が多数残る** 傾向 |
| **ワーストフィット** | **最大の** 空き領域に割り当てる | 残る空き領域が大きくなる |

- **フラグメンテーション（断片化）**：割当てと解放を繰り返すうちに、空き領域が細切れになり、合計は十分なのに大きなプログラムを置けなくなる現象。
- **コンパクション（メモリの再配置）**：使用中の領域を移動して、細切れの空き領域を1つにまとめること。
- **ガーベジコレクション**：プログラムが使い終わった（どこからも参照されなくなった）メモリ領域を自動的に回収すること。
- **メモリリーク**：確保したメモリを解放し忘れて、使える領域がだんだん減っていく不具合。

:::exam R7秋 午前問5
ベストフィット方式の特徴を選ぶ問題。「要求された大きさを満たす最小の空きブロックを割り当てるので、最終的には小さな空きブロックが多数残る傾向にある」が正解です。
:::

### 仮想記憶

**仮想記憶** とは、補助記憶（ディスク）の一部を使って、**実際の主記憶よりも大きな記憶空間があるように見せる** 仕組みです。プログラムは仮想的なアドレス（**仮想アドレス**）を使い、OSとハードウェア（MMU）が実際のアドレス（**実アドレス**）に変換します。

- **ページング方式**：記憶領域を固定長の「**ページ**」に分けて管理する。必要なページだけを主記憶に置く。
- **セグメント方式**：プログラムの論理的なまとまり（可変長のセグメント）単位で管理する。
- **ページフォールト**：必要なページが主記憶にないときに発生する割込み。OSがディスクからページを読み込む（**ページイン**）。主記憶に空きがなければ、どれかのページをディスクに追い出す（**ページアウト**）。
- **スラッシング**：主記憶が足りず、ページイン／ページアウトが頻発して、処理がほとんど進まなくなる状態。
- **TLB**：仮想アドレスから実アドレスへの変換結果を記憶しておく高速なバッファ。

### ページ置換えアルゴリズム

主記憶がいっぱいのとき、どのページを追い出すかを決める方式です。

| 方式 | 追い出すページ |
|---|---|
| **FIFO** | **最も昔に** 主記憶に読み込まれたページ |
| **LRU**（Least Recently Used） | **最後に参照されてから最も時間が経っている**（最も長く使われていない）ページ |
| **LFU**（Least Frequently Used） | **参照された回数が最も少ない** ページ |

:::calc LRU のページフォールト回数
ページ枠3つ、ページ参照順「1, 2, 3, 1, 4, 2」、最初は空。
1:フォールト[1] → 2:フォールト[1,2] → 3:フォールト[1,2,3] → 1:ヒット（1が最近使われた）→ 4:フォールト。最も長く使われていないのは2なので2を追い出す[1,3,4] → 2:フォールト。最も長く使われていない3を追い出す[1,4,2]
ページフォールトは **5回**。
:::

## 4. ファイル管理

- **ディレクトリ**：ファイルを分類して整理するための入れ物（フォルダ）。階層構造（木構造）になっている。
- **絶対パス**：最上位（ルート）からの道筋で表す（例：/home/user/a.txt）。
- **相対パス**：現在いるディレクトリ（カレントディレクトリ）からの道筋で表す。「..」は1つ上（親）のディレクトリ、「.」は現在のディレクトリ。

### バックアップの方式

| 方式 | バックアップする範囲 | 復元に必要なもの |
|---|---|---|
| **フルバックアップ** | すべてのデータ | フルバックアップだけ |
| **差分バックアップ** | **前回のフルバックアップ以降** に変更されたデータ | フル ＋ 最新の差分 |
| **増分バックアップ** | **前回のバックアップ（種類を問わず）以降** に変更されたデータ | フル ＋ それ以降のすべての増分 |

## 5. 開発ツールと OSS

### 言語処理の流れ

ソースプログラム →（**コンパイラ**）→ 目的プログラム →（**リンカ（連係編集）**）→ ロードモジュール →（**ローダ**）→ 主記憶に読み込んで実行。

- **静的リンク**：実行前にライブラリを組み込む。**動的リンク**：実行時に必要なライブラリを呼び出す（DLLなど）。
- **プリプロセッサ**：コンパイルの前に、マクロの展開などの前処理を行う。
- **最適化**：コンパイラが、実行速度やサイズが良くなるように目的プログラムを改善すること。

### OSS（オープンソースソフトウェア）

ソースコードが公開され、誰でも利用・改変・再配布できるソフトウェアです。ライセンスの条件を守る必要があります。

- **GPL**：改変して配布する場合、そのソースコードも同じ GPL で公開しなければならない（**コピーレフト**）。
- **MIT ライセンス・BSD ライセンス**：著作権表示などを残せば、改変後のソースを公開しなくてよい。商用製品に組み込みやすい。
- 代表的な OSS：Linux（OS）、Apache・Nginx（Webサーバ）、MySQL・PostgreSQL（DBMS）、Git（バージョン管理）。

:::sum
- タスクは 実行可能・実行・待ち の3状態。待ちから直接実行には移らない。
- 処理時間順は「到着済みの中で最短」を選ぶ。ラウンドロビンはタイムクウォンタムで交代。
- 排他制御はセマフォ（P操作で確保、V操作で解放）。デッドロックは資源獲得順序をそろえて防ぐ。
- ベストフィットは最小の空きを使い、小さな空きが多数残る。
- 仮想記憶：ページフォールトでページイン。LRU は最も長く参照されていないページを追い出す。
- 差分は「前回フル以降」、増分は「前回バックアップ以降」。GPL はコピーレフト。
:::
