## テクノロジ系の補遺

| 用語 | 意味 |
|---|---|
| 1オペランド形式・2オペランド形式 | 命令が持つアドレス（オペランド）の数。1つの場合はもう一方にアキュムレータを使う |
| 命令の種類 | 算術演算命令、論理演算命令、転送命令（データの移動）、比較命令、シフト命令、分岐命令、入出力命令 |
| 補数器・乗算器 | 補数を作る回路 ／ 掛け算を行う回路（ALUの構成要素） |
| 絶対アドレス指定 | 命令中のアドレスがそのまま主記憶の番地を示す方式 |
| 超並列プロセッサ | 数千〜数万個のプロセッサを結合して並列に処理するコンピュータ |
| バスの分類 | **システムバス**（CPU・メモリ間）、**入出力バス**（周辺装置との間）、**シリアルバス**（1本の線で1ビットずつ：USB、PCI Express）、**パラレルバス**（複数の線で同時に：旧来のPCI） |
| IEEE 1394 | 映像機器などを接続する高速シリアルインタフェース（FireWire） |
| 接続形態 | **スター接続**（ハブを中心）、**カスケード接続**（ハブを多段に）、**ツリー接続**、**デイジーチェーン接続** |
| プログラム制御方式 | CPUが入出力の制御をすべて行う方式（DMA方式と対比） |
| ボリュームラベル・見出しラベル | 記憶媒体の識別情報 ／ ファイルの先頭に付ける識別情報 |
| チャンクサイズ | RAIDでストライピングするときにデータを分割する単位の大きさ |
| 予備切替・並列運転 | 故障時に予備の装置に切り替える ／ 複数の装置を同時に運転して負荷を分け合う |
| 競合制御 | 複数のアクセスが同じ資源を同時に使おうとしたときに調整する制御 |
| リンケージエディタ | 複数の目的プログラムやライブラリを結合して、実行可能なプログラム（ロードモジュール）を作るプログラム（リンカ） |
| マルチブート・ネットワークブート | 1台のPCに複数のOSを入れて起動時に選ぶ ／ ネットワーク上のサーバからOSを読み込んで起動する |
| タイムスライス方式 | 一定時間（タイムスライス）ごとにCPUを切り替えるスケジューリング（ラウンドロビン） |
| 静的・動的優先順位方式 | 優先度を最初に決めて変えない ／ 実行状況に応じて優先度を変える |
| IOCS・チャネル制御方式 | 入出力制御システム ／ チャネル（入出力専用のプロセッサ）に入出力を任せる方式 |
| 単一連続割当て・ベースアドレス方式 | 主記憶を1つのプログラムに連続して割り当てる ／ ベースレジスタの値を加えて実アドレスを求め、プログラムを任意の位置に置けるようにする |
| 多重仮想空間方式 | プロセスごとに独立した仮想アドレス空間を持たせる方式（単一仮想空間方式はすべてで1つを共有） |
| 多重レベルセキュリティ | 情報に「極秘・秘・社外秘」などのレベルを付け、利用者のレベルに応じてアクセスを制御する |
| ファイル編成 | **順編成**（先頭から順に格納）、**索引順編成**（索引で直接アクセスもできる。入りきらないレコードは **あふれ域** に格納）、**直接編成**（キーから **ハッシング** で格納位置を計算）、**区分編成** |
| ブロック化・デブロッキング | 複数の論理レコードを1ブロックにまとめる ／ ブロックから個々の論理レコードを取り出す |
| 階層型ディレクトリ・パス名 | ディレクトリを木構造で管理する方式 ／ ファイルの位置を表す道筋（絶対パス・相対パス） |
| 多重バックアップ | 複数の世代や媒体にバックアップを取ること（世代管理） |
| CPAN・PEAR | Perl・PHPのライブラリを集めた公開リポジトリ |
| Eclipse | Javaなどで広く使われるOSSの統合開発環境（IDE） |
| FreeBSD・NetBSD・OpenBSD | BSD系のOSSのUNIX系OS |
| BiCMOS・CORDIC | バイポーラとCMOSを組み合わせた回路技術 ／ 三角関数などを加算とシフトだけで計算するアルゴリズム |
| 論理圧縮 | カルノー図などで論理式を簡単にし、回路を小さくすること |
| 空間近接原理 | 関連する情報は近くに配置すると、ひとまとまりと認識されやすい（ゲシュタルトの近接の法則） |
| スクローリーテリング | ページをスクロールするにつれて物語のように情報が展開していく表現手法 |
| ビジュアルリグレッションテスト | 変更前後の画面を画像として比較し、見た目の意図しない変化を検出するテスト |
| 入力方式 | **穴埋め方式**（決まった欄に入力）、**メニューインプット方式**（一覧から選択）、**部分送信**（入力の一部ずつサーバに送る） |
| 入力エラーの種類 | フォーマットエラー（形式の誤り）、論理エラー（内容の矛盾）、シーケンスエラー（順序の誤り） |
| ISO 9241 | 人間とシステムのインタラクションの人間工学に関する国際規格（ユーザビリティの定義を含む） |
| QuickTime・Motion JPEG | Appleのマルチメディア形式 ／ フレームごとにJPEGで圧縮する動画形式（編集しやすい） |
| ルックアップテーブル・フォトレタッチ | 入力値に対する出力値を表にして高速に変換する（色の変換など） ／ 写真の加工・修正 |
| オーサリング・DTP | 文字・画像・音声などを組み合わせてコンテンツを作ること ／ パソコンで印刷物の編集・レイアウトを行うこと |
| バックマン線図 | 網型データベースのレコード型と親子集合を図で表したもの |
| 存在制約 | 関連するエンティティが存在しなければ、そのエンティティも存在できないという制約 |
| モジュール言語 | SQL文を手続（モジュール）として定義し、プログラムから呼び出す方式 |
| IRDS | 情報資源辞書システム。データ辞書を管理するシステムの標準 |
| ファクトデータベース・リファレンスデータベース | 数値や事実そのものを収録したDB ／ 文献の所在などを案内するDB |
| X・V・Iシリーズ | ITU-Tの勧告の分類。X（データ通信網）、V（電話網でのデータ通信）、I（ISDN） |
| TELNET | 遠隔のコンピュータにログインして操作するプロトコル。暗号化されないので現在はSSHを使う |
| 分散オブジェクト技術 | ネットワーク上に分散したオブジェクトを、ローカルのように呼び出す技術（CORBAなど） |
| 検索エンジンの種類 | **ロボット型**（クローラが自動でWebを巡回して索引を作る）、**ディレクトリ型**（人が分類して登録） |
| 間欠受信・ドーマント | モバイル端末が受信を一定間隔で休んで省電力化する ／ 通信していないときに無線の接続を休止状態にする |
| Diameter | RADIUSの後継となる認証・認可・課金（AAA）のプロトコル |
| トラステッドOS | セキュアOSと同様に、強制アクセス制御などで高い安全性を確保したOS |
| MACアドレスフィルタリング | 登録したMACアドレスの端末だけを接続させる。MACアドレスは偽装できるので単独では不十分 |
| SSL/TLSアクセラレータ | 暗号処理を専用装置で肩代わりし、サーバの負荷を減らす |
| セキュアエレメント | 鍵などの重要情報を安全に保管する耐タンパ性のあるチップ（スマホ決済など） |
| 物理的な対策の補足 | USBキー（認証用の鍵）、セキュリティケーブル（盗難防止のワイヤー）、機械警備（センサーによる警備）、装置の安全な廃棄（データ消去・物理破壊） |
| エージェント指向 | 自律的に判断して動作するソフトウェア（エージェント）の協調でシステムを構成する考え方 |
| 源泉と吸収 | DFDで、データの発生源と行き先（外部実体）のこと |
| 設計の図式 | **バブルチャート**（DFDの別名）、**イベントトレース図**（オブジェクト間のイベントの流れ）、**DSD**、**プログラミングテーブル**（決定表形式でプログラムを表す） |
| フォームオーバーレイ | 帳票の罫線などの定型部分と、データを重ねて印刷・表示する方式 |
| コンポーネントウェア | 部品（コンポーネント）を組み合わせてソフトウェアを構築する手法。**ブラックボックス型**（中身を変えずに使う）と **ホワイトボックス型**（中身を変更して使う） |
| コード支援機能 | コード補完、オートインデント、シンタックスハイライト（色分け）、ブレークポイント（デバッグで実行を止める位置）、コードオーディター（規約違反の検査） |
| 経路組合せ網羅 | プログラムのすべての実行経路の組合せを網羅するテスト（最も厳しいが現実的でないことが多い） |
| 原因結果グラフ法 | 入力条件（原因）と出力（結果）の関係をグラフにし、決定表を作ってテストケースを作る技法 |
| ソフトウェア部品の分類 | 関数部品、データ部品、プロセス部品、パラメトリック部品（パラメータで振る舞いを変えられる） など |
| コールグラフ | プログラム中の関数（手続）の呼出し関係を表した図 |
| User-Agent | Webブラウザなどがサーバに送る、自分の種類やバージョンを示す情報 |
| モバイルアプリ開発の留意点 | パーミッション要求（位置情報などの利用許可）、端末の画面サイズの多様性、圏外・着信時の動作、ストアの審査と配布 |
| VDM・完全適合・修整適合 | 形式仕様記述手法 ／ 規格（JIS X 0160など）のすべてを満たす ／ テーラリングして一部を満たす |
| EJB | Javaのサーバ側の部品（コンポーネント）の仕様 |

## マネジメント系の補遺

| 用語 | 意味 |
|---|---|
| プロジェクトガバナンス | プロジェクトの意思決定の枠組み・権限・責任を定めること |
| プロジェクト作業規定書・スコープ規定書 | プロジェクトで行う作業の内容を記述した文書 ／ スコープ（成果物と作業範囲）を定めた文書 |
| 変更登録簿・問題点管理表 | 変更要求とその処理状況の記録 ／ 発生した課題とその対応状況の一覧 |
| 大日程・中日程・小日程計画 | プロジェクト全体の主要な節目（マスタスケジュール） ／ 工程ごとの計画 ／ 週単位などの詳細な作業計画 |
| コンフリクトマネジメント | チーム内の対立を適切に解決すること（協調・妥協・強制・撤退・鎮静） |
| JIS Q 9001 | 品質マネジメントシステムの要求事項（ISO 9001） |
| 力量 | 意図した結果を出すために知識と技能を適用する能力。マネジメントシステム規格で要求される |
| JIS X 0164 | ソフトウェア資産管理（ITアセットマネジメント）の規格群 |
| 構成識別 | 管理対象とする構成品目（CI）を選び、識別子を付けること |
| 移行判断・運用引継ぎ | 移行の準備が整ったかを判断して本番移行を決める ／ 開発部門から運用部門へ必要な情報と体制を引き継ぐ |
| IPPF | 内部監査人協会（IIA）が定めた、内部監査の国際的な基準の枠組み |
| PRM-IT | IT管理のプロセスを体系化した参照モデル |
| 監査の種類の補足 | 金融商品取引法監査・会社法監査（法定の会計監査）、経営監査（経営活動全般の有効性） |
| データサンプリング | 大量のデータから一部を抽出して監査すること |
| システム管理基準追補版 | 財務報告に係るIT統制の整備・評価のための指針（J-SOX対応） |

## ストラテジ系の補遺

| 用語 | 意味 |
|---|---|
| 同質化戦略 | リーダー企業が、チャレンジャーの差別化策を模倣して効果を打ち消す戦略 |
| コ・クリエーション | 企業と顧客などが協働して新しい価値を共に創ること（共創） |
| アサエルの購買行動類型 | 製品への関与の高さとブランド間の差の大きさで、購買行動を4つに分類したもの |
| DEARフレームワーク・アサンプションマップ | 新規事業のアイデアを検証するための枠組み ／ 事業の前提（仮説）を重要度と確からしさで整理する図 |
| UXタイムスパン | 予期的UX（使う前）・一時的UX（使用中）・エピソード的UX（使用後の振り返り）・累積的UX（長期的） |
| 顧客価値ヒエラルキー | 製品の価値を、中核的な便益 → 基本製品 → 期待製品 → 膨張製品 → 潜在製品の階層で捉える考え方 |
| PLM | 製品の企画から設計・生産・廃棄までのライフサイクル全体の情報を一元管理すること |
| ライフサイクルエクステンション | 成熟期の製品の寿命を、新用途や改良で延ばす戦略 |
| パブリシティ | 報道機関にニュースとして取り上げてもらう広報活動（広告費がかからない） |
| マーケティングの種類 | マス、ターゲット、リレーションシップ（顧客との長期的関係）、ダイレクト（顧客に直接働きかける）、クロスメディア（複数の媒体を組み合わせる） |
| MFTフレームワーク | 市場（Market）・製品（Function）・技術（Technology）の3層で、技術と市場の結び付きを整理する |
| 早期審査制度 | 一定の条件を満たす特許出願の審査を早く行う制度 |
| 産学官連携 | 企業・大学・国が協力して研究開発を進めること |
| AI関連の指針 | **AI事業者ガイドライン**（日本：開発者・提供者・利用者の取組み）、**信頼できるAIのための倫理ガイドライン**（EU）、**倫理的に調和した設計**（IEEE）、**人工知能学会倫理指針**、**AI-Ready**（AIを活用できる組織への成熟度） |
| AIサービスのオプトアウト | 利用者が、自分のデータをAIの学習に使わせないように選択できること |
| EDIの規約・標準の補足 | 基本取引規約（取引の契約）、業務運用規約（業務の取決め）、**JCA手順・JX手順**（流通業界の通信手順）、**UN/CEFACT・EANCOM**（国際的なEDI標準）、**STEP**（製品の設計データ交換の標準） |
| ソフトウェアファースト | ハードウェアよりソフトウェアを先に考え、ソフトで価値を生み出す製品開発の考え方 |
| グリーンスローモビリティ | 時速20km未満で走る電動の公共交通（地域の移動手段） |
| 科学的管理法・経営過程論 | テイラーが提唱した、作業を標準化して能率を高める管理法 ／ ファヨールが提唱した、計画・組織・指揮・調整・統制という管理の過程 |
| エンプロイヤビリティ・アルムナイ採用 | 他社でも雇用されうる能力 ／ 退職した元社員を再雇用すること |
| グループダイナミクス | 集団の中で人の行動や考えがどう影響し合うかを研究する分野（集団力学） |
| 内発的動機づけ | 報酬ではなく、興味や達成感など内面から生まれる意欲 |
| SRI・企業市民 | 社会的責任投資 ／ 企業も社会の一員として社会に貢献すべきという考え方 |
| アジャイル・ガバナンス | 変化の速い技術に対し、規制やルールを柔軟に見直しながら統治する考え方 |
| カーボンフットプリント | 製品のライフサイクル全体で排出される温室効果ガスの量を表示すること |
| データスペース | 企業や組織をまたいで、信頼性を保ちながらデータを共有・流通させるための仕組み |
| 配分問題・輸送問題 | 限られた資源を最適に配分する問題 ／ 複数の工場から複数の需要地へ、輸送費が最小になる輸送量を求める問題（いずれも線形計画法で解く） |
| 展開型ゲーム | プレイヤーが順番に手を打つゲームを、木の形で表したもの（戦略型ゲームは同時に手を選ぶ） |
| 要求水準原理・最尤未来原理 | 目標の水準を満たす確率が最も高い案を選ぶ ／ 最も起こりやすい状況だけを想定して最善の案を選ぶ |
| G-P分析 | 良い（Good）グループと悪い（Poor）グループを比較して、品質の差の原因を探る分析 |
| データ前処理 | ストップワード除去（「の」「は」など意味の薄い語を除く）、二値化、離散化、対数変換、季節調整、欠損値の補完 |
| データ同化 | 観測データをシミュレーションに取り込んで、予測の精度を高める手法（天気予報など） |
| データのサイロ化 | 部門ごとにデータが分断され、組織全体で活用できない状態 |
| 可視化の補足 | モザイク図（クロス集計の割合を面積で表す）、散布図行列、2軸グラフ、シェープファイル（地図データの形式）、共起キーワード（一緒に出現しやすい語） |
| 利益図表・費用分解 | 損益分岐点図表（売上高線と総費用線の交点が損益分岐点） ／ 費用を固定費と変動費に分けること |
| 変動損益計算書 | 売上高から変動費を引いて限界利益を出し、さらに固定費を引いて利益を出す形式の損益計算書 |
| 精算表・繰延資産 | 試算表から財務諸表を作るための一覧表 ／ 支出の効果が将来に及ぶため資産として計上する費用（開業費など） |
| 時価会計・退職給付会計 | 資産を時価で評価する ／ 将来の退職金を見積もって負債に計上する |
| 財務分析の手法 | 趨勢法（年度ごとの推移）、構成比率（全体に占める割合）、関係比率（項目どうしの比） |
| ネッティング・オフバランス | グループ企業間の債権債務を相殺して決済を減らす ／ 貸借対照表に載らない取引 |
