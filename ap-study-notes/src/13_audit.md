## 1. システム監査の基本

### システム監査の目的と基準

- **目的**：情報システムにまつわるリスクに適切に対処しているかを、独立かつ専門的な立場で点検・評価・検証し、**ガバナンス・マネジメント・コントロールが適切であるという保証を与える**、または **改善のための助言を行う**。
- **システム監査基準**：監査人の行動規範（監査をどう行うか）を定めたもの。
- **システム管理基準**：監査の際の **判断の尺度**（システムがどうあるべきか）を定めたもの。
- **保証型監査**：適切であることを保証する。**助言型監査**：改善点を助言する。

### システム監査人の独立性

監査人は、公正な判断をするために、監査対象から独立していなければなりません。

- **外観上の独立性**：監査対象の部門に所属していない、利害関係がないなど、**外から見ても** 独立していること。例えば、開発を担当した人が、そのシステムを監査してはいけない。
- **精神上の独立性**：偏りのない、**公正かつ客観的な** 姿勢で判断すること。
- 監査人は **改善を指示・命令する権限を持たない**。あくまで改善を **勧告（提案）** する立場。改善を実施するのは監査対象の部門（被監査部門）であり、改善を指示するのは経営者。

:::trap 監査人は「改善の実施」をしない
「監査人が問題点を修正した」「監査人が改善を指示した」という選択肢は誤りです。監査人は、指摘事項と改善提案を監査報告書にまとめて **依頼者（経営者など）に報告** し、改善の状況を **フォローアップで確認** するまでが役割です。
:::

## 2. 監査証拠と監査技法

### 監査証拠と監査調書

- **監査証拠**：監査人が結論（監査意見）を出すための根拠となる事実。文書、記録、ログ、ヒアリング結果など。
- **監査調書**：監査人が実施した監査手続の内容や、入手した監査証拠、結論に至った過程を記録した文書。**監査の結論の裏付け** となる。
- 監査証拠は、十分かつ適切でなければならない。

### 監査技法

| 技法 | 内容 |
|---|---|
| **チェックリスト法** | あらかじめ作成した質問のリストに回答してもらう |
| **ドキュメントレビュー法** | 関連する文書（規程、設計書、議事録）を閲覧して確認する |
| **インタビュー法** | 関係者に直接質問して回答を得る |
| **ウォークスルー法** | データの生成から出力までの流れを、記録をたどって追跡する |
| **突合・照合法** | 関連する複数の記録を突き合わせて、一致しているか確認する |
| **現地調査法** | 実際に現場に出向いて、作業の状況を観察する |
| **CAAT（コンピュータ支援監査技法）** | 監査人がコンピュータを使って監査する。**テストデータ法**（監査人が用意したデータを処理させ、結果を予想と比べる）、**ITF法**（本番システムに監査用の架空口座を設けて処理を確認する）、**並行シミュレーション法**（監査人が作ったプログラムと本番システムに同じデータを処理させ、結果を比べる）など |

:::point 監査の問題の解き方
「〇〇を確かめるために、監査人が確認すべき監査証拠（記録）はどれか」という問題が多く出ます。「何を確かめたいのか」と「その事実を **客観的に** 示す記録は何か」を結び付けて考えます。例：アクセス権限の見直しが定期的に行われているか → 権限の見直しの **実施記録**（承認の記録）を確認する。
:::

## 3. 内部統制

### 内部統制とは

**内部統制** とは、企業が健全かつ効率的に事業を行うために、**組織内部で整備・運用するルールや仕組み** です。経営者が整備の責任を持ちます。

**4つの目的**

- 業務の有効性及び効率性
- 報告の信頼性（財務報告など）
- 事業活動に関わる法令等の遵守
- 資産の保全

</div><div markdown="1">

**6つの基本的要素**

- 統制環境（組織の気風、経営者の姿勢）
- リスクの評価と対応
- 統制活動（承認、職務分掌など）
- 情報と伝達
- モニタリング（監視活動）
- **IT（情報技術）への対応**

</div></div></div></div>

- **職務分掌**：1人に権限が集中しないように、担当業務を分けること。例えば、「発注の担当者」と「その発注を承認する人」を別にする。「プログラムを開発する人」と「本番環境に移行する人（運用者）」を分ける。不正やミスの防止に重要。
- **J-SOX（内部統制報告制度）**：上場企業に、財務報告に関する内部統制を評価した **内部統制報告書** の提出を義務付ける制度（金融商品取引法）。
- **IT全般統制**：ITを利用した業務全体を支える基盤の統制（システムの開発・変更管理、運用管理、アクセス管理など）。
- **IT業務処理統制**：個々の業務処理が正しく行われることを確保する統制（入力データのチェック、エラー処理など）。

## 4. ITガバナンスとコンプライアンス

- **ITガバナンス**：**経営者が主導** して、ITを活用するための戦略を立て、IT投資の効果やリスクを適切に管理・統制する仕組み。JIS Q 38500 では「**評価（Evaluate）・指示（Direct）・モニタ（Monitor）**」の3つのタスクを示している。
- **コーポレートガバナンス（企業統治）**：経営者を監視し、企業が健全に経営されるようにする仕組み（社外取締役の設置など）。
- **コンプライアンス（法令遵守）**：法律だけでなく、社会規範や企業倫理を守ること。
- **COBIT**：ITガバナンスのフレームワーク。

## 5. 過去問（令和2〜6年度）で問われた発展テーマ

### システム監査基準・システム管理基準（令和5年改訂）

- **システム監査基準（令和5年）**：システム監査人の行為規範。監査人には **独立性・客観性・職業倫理**、専門的な能力、**正当な注意（職業的懐疑心）** が求められる。監査は、**リスクに基づいて** 対象や手続を決める（リスクアプローチ）。
- **システム管理基準（令和5年）**：組織が IT ガバナンスを実現するための実践規範。監査では判断の尺度として使う。
- **監査調書**：監査人が行った監査手続の内容、入手した監査証拠、結論を記録したもの。**監査意見の根拠** となるので、必ず作成し、適切に保管する。
- **フォローアップ**：監査報告後、被監査部門が改善提案に対して **改善を実施しているかを確認** する。改善が遅れている場合も、監査人が自ら改善したり、改善の実施を指示したりするのではなく、状況を確認して依頼者に報告する。

### 情報セキュリティ監査

- **情報セキュリティ監査制度**：経済産業省の「情報セキュリティ管理基準」を判断の尺度として、組織の情報セキュリティ対策を監査する制度。
- **保証型監査**：対策が適切であることを **保証** する（監査報告書に「適切である」という意見を表明する）。
- **助言型監査**：問題点を指摘し、**改善のための助言** を行う。

### 監査の着眼点の例

| 監査対象 | 確認すべきこと（例） |
|---|---|
| **アジャイル開発** | プロダクトオーナーが優先順位を決めているか、短いサイクルで利用者の評価を受けているか、ドキュメントが必要最小限でも品質が確保されているか |
| **ログ管理** | ログの取得対象・保存期間が決められているか、ログの **改ざん防止** やアクセス制限がされているか、定期的に分析しているか |
| **BCP（事業継続計画）** | 重要業務と目標復旧時間が定められているか、**定期的に訓練・見直し** が行われているか |
| **入出力データ** | 入力データの承認・チェックの仕組みがあるか、不要になった出力帳票が廃棄されているか |
| **外部委託** | 委託先の選定基準、契約内容、委託先の管理状況（報告・監査）を確認しているか |
| **AI の開発計画** | 学習データの品質や偏り、AI の判断の説明性、利用者への影響が考慮されているか（令和6年度秋期 午後問11） |
| **コンティンジェンシー計画** | 障害時の代替手段や連絡体制が定められ、訓練で実効性が確かめられているか（令和5年度秋期 午後問11） |

### 内部統制の関係者と統制の種類

- **経営者**：内部統制を整備・運用する **最終的な責任** を持つ。
- **取締役会**：経営者の内部統制の整備・運用を **監督** する。
- **監査役等**：取締役の職務執行を監査する。
- **内部監査人**：内部統制の整備・運用状況を **モニタリング（検討・評価）** し、改善を促す。
- **予防的統制**：不正や誤りの発生を **事前に防ぐ**（承認、アクセス制限）。**発見的統制**：発生した不正や誤りを **事後に発見する**（照合、ログの点検）。
- **IT に係る業務処理統制**：個々のアプリケーションで、入力データの正確性・網羅性のチェック、エラーデータの修正・再処理、マスタデータの維持管理などを行う。
- **手作業によるコントロールとの組合せ**：パッケージの標準機能だけで不足する統制を、手作業の確認（照合・承認）で補う。その場合は、手作業が確実に行われた記録を監査証拠として確認する（令和6年度春期 午後問11）。

:::sum
- 監査は 計画 → 予備調査 → 本調査 → 報告 → フォローアップ。報告先は依頼者（経営者など）。
- 監査人は外観上・精神上の独立性が必要。改善は勧告するだけで、指示や実施はしない。
- 監査調書は結論の裏付け。CAAT：テストデータ法、ITF法、並行シミュレーション法。
- 内部統制の要素に「ITへの対応」。職務分掌で権限を分ける。
- ITガバナンスは経営者が主導（評価・指示・モニタ）。
:::
