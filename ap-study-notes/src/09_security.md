## 1. リスクと脅威

### 情報セキュリティリスクの考え方

- **情報資産**：守るべき価値のある情報やシステム（顧客データ、サーバなど）。
- **脅威**：情報資産に損害を与える可能性のある原因（攻撃者、ウイルス、災害、誤操作）。
- **脆弱性**：脅威につけ込まれる弱点（ソフトウェアのバグ、設定ミス、パスワードの使い回し）。
- **リスク**：脅威が脆弱性を突いて、損害が発生する可能性。**リスク ＝ 資産価値 × 脅威 × 脆弱性** のように評価する。

### リスクマネジメント

**リスクアセスメント** ＝ リスク特定 → リスク分析 → リスク評価。その後、評価結果に応じて **リスク対応** を選びます。

| リスク対応 | 内容 | 例 |
|---|---|---|
| **リスク回避** | リスクの原因そのものをなくす | 危険なサービスを廃止する |
| **リスク低減** | 対策を講じて発生確率や影響を下げる | ウイルス対策ソフトの導入 |
| **リスク移転（共有）** | 他者に移す | 保険に入る、外部委託する |
| **リスク保有（受容）** | 影響が小さいので、そのまま受け入れる | 対策費用の方が高い場合 |

## 2. 攻撃手法

### マルウェア

**マルウェア** とは、悪意のあるソフトウェアの総称です。

| 種類 | 特徴 |
|---|---|
| **ウイルス** | 他のプログラムに寄生して感染を広げる |
| **ワーム** | 単独で動作し、ネットワーク経由で自己増殖する |
| **トロイの木馬** | 有用なソフトを装って侵入し、裏で不正な動作をする |
| **ランサムウェア** | ファイルを暗号化して使えなくし、元に戻すための **身代金** を要求する |
| **ボット** | 感染した端末を、外部の指令サーバ（**C&Cサーバ**）から遠隔操作できるようにする |
| **スパイウェア／キーロガー** | 利用者の情報やキー入力を盗み、外部に送る |
| **ルートキット** | 侵入の痕跡を隠すためのツール群 |
| **ファイルレスマルウェア** | ファイルをディスクに保存せず、メモリ上やOS標準のツールで動作するため検知しにくい |

### パスワードに対する攻撃

| 攻撃 | 内容 | 対策 |
|---|---|---|
| **ブルートフォース攻撃（総当たり）** | 考えられるすべての文字の組合せを試す | 試行回数制限（アカウントロック） |
| **辞書攻撃** | よく使われる単語のリストで試す | 推測されにくいパスワード |
| **リバースブルートフォース攻撃** | パスワードを1つ固定し、利用者IDを次々に変えて試す（ロックされにくい） | 多要素認証 |
| **パスワードリスト攻撃** | 他のサイトから漏えいしたIDとパスワードの組を使って試す | **パスワードの使い回しをしない** |
| **レインボーテーブル攻撃** | ハッシュ値から元のパスワードを逆引きする表を使う | **ソルト**（ランダムな値）を付けてからハッシュ化 |

### Web アプリケーションへの攻撃

| 攻撃 | 何をされるか | 主な対策 |
|---|---|---|
| **SQLインジェクション** | 入力欄に SQL の断片を入れ、DBを不正に操作（情報漏えい・改ざん）する | **プレースホルダ**（バインド機構）を使う、入力値のエスケープ |
| **クロスサイトスクリプティング（XSS）** | 悪意のあるスクリプトを Web ページに埋め込み、閲覧者のブラウザで実行させる（Cookie の盗取など） | 出力時の **エスケープ（サニタイジング）**、Cookie に HttpOnly 属性 |

| **セッションハイジャック** | セッションIDを盗んで、正規の利用者になりすます | セッションIDを推測困難にし、ログイン後に再発行、HTTPS |
| **クリックジャッキング** | 透明なページを重ねて、意図しないボタンを押させる | X-Frame-Options ヘッダ |

### ネットワークへの攻撃

| 攻撃 | 内容 |
|---|---|
| **DoS / DDoS 攻撃** | 大量の通信を送りつけて、サービスを停止させる。多数の端末（ボット）から行うのが DDoS |
| **DNS キャッシュポイズニング** | DNS サーバに偽の情報を覚えさせ、利用者を偽サイトに誘導する |
| **中間者攻撃（MITM）** | 通信の間に割り込み、盗聴や改ざんを行う |
| **ポートスキャン** | どのポートが開いているかを調べ、攻撃の糸口を探す（攻撃の下調べ） |
| **IP スプーフィング** | 送信元 IP アドレスを偽装する |
| **リフレクション攻撃（反射型DDoS）** | 送信元を攻撃対象に偽装して問合せを送り、大きな応答を攻撃対象に送りつけさせる（DNSアンプ攻撃など） |

### 人や組織を狙う攻撃

- **ソーシャルエンジニアリング**：技術ではなく、人の心理的な隙を突いて情報を盗む（電話で上司になりすましてパスワードを聞き出す、肩越しにのぞく **ショルダーハッキング**、ゴミ箱をあさる **トラッシング**）。
- **フィッシング**：実在の組織を装ったメールで偽サイトに誘導し、IDやパスワードを入力させる。
- **標的型攻撃**：特定の組織を狙い、業務に関係ありそうなメールでマルウェアを送り込む。長期間潜伏するものは **APT（持続的標的型攻撃）**。
- **水飲み場型攻撃**：標的がよく見るWebサイトを改ざんし、閲覧しただけで感染させる。
- **ビジネスメール詐欺（BEC）**：取引先や経営者になりすましたメールで、偽の口座に送金させる。
- **ゼロデイ攻撃**：脆弱性が発見されてから、修正プログラムが提供される **前に** 行われる攻撃。
- **サプライチェーン攻撃**：セキュリティの弱い取引先や、ソフトウェアの更新の仕組みを経由して標的に侵入する。

## 3. 暗号技術

### 暗号の基本用語

- **平文**：暗号化する前のデータ。**暗号文**：暗号化した後のデータ。
- **暗号化**：平文を、鍵を使って第三者に読めない暗号文に変換すること。**復号**：暗号文を元の平文に戻すこと。
- **鍵**：暗号化・復号に使う秘密の値。

### 共通鍵暗号方式と公開鍵暗号方式

<div class="fig" markdown="1"><div class="fig-t">第9章③ 2つの暗号方式の比較</div><div class="fig-b" markdown="1">

| | 共通鍵暗号方式 | 公開鍵暗号方式 |
|---|---|---|
| 鍵 | 暗号化と復号で **同じ鍵** を使う | **公開鍵** と **秘密鍵** のペアを使う |
| 暗号化 → 復号 | 共通鍵 → 共通鍵 | **受信者の公開鍵** で暗号化 → **受信者の秘密鍵** で復号 |
| 処理速度 | **速い** | 遅い |
| 鍵の数（n人で通信） | n(n−1)/2 個（多い） | 2n 個（1人1ペア） |
| 課題 | 鍵を安全に相手に渡す方法（鍵配送問題） | 公開鍵が本人のものかの証明（→ PKI） |
| 代表例 | **AES**（DESの後継） | **RSA**（素因数分解の難しさを利用）、**楕円曲線暗号** |

</div></div>

:::calc 必要な鍵の数
10人が互いに暗号通信する。共通鍵暗号方式では、ペアごとに別の鍵が必要 → 10 × 9 ÷ 2 ＝ **45個**。公開鍵暗号方式では1人1ペア → 10 × 2 ＝ **20個**。
:::

:::note ハイブリッド暗号方式
実際の通信（TLS など）では、両方のいいとこ取りをします。データ本体は **速い共通鍵** で暗号化し、その共通鍵を **公開鍵暗号** で暗号化して相手に送ります。これで「速さ」と「鍵配送問題の解決」を両立できます。
:::

### ハッシュ関数

**ハッシュ関数** は、任意の長さのデータから、**固定長の値（ハッシュ値・メッセージダイジェスト）** を作る関数です。

- 同じデータからは必ず同じハッシュ値ができる。データが1ビットでも変わると、まったく違う値になる → **改ざん検知** に使える。
- ハッシュ値から元のデータを復元できない（**一方向性**）→ パスワードの保存に使える。
- 同じハッシュ値になる別のデータを見つけるのが極めて困難（**衝突発見困難性**）。
- 代表例：**SHA-256**（SHA-2 ファミリ）、SHA-3。MD5、SHA-1 は安全性が低下しているので非推奨。
- **HMAC**：共通鍵とハッシュ関数を組み合わせて、メッセージ認証コード（MAC）を作る。改ざん検知と送信者の確認ができる。

### デジタル署名

**デジタル署名** は、「**送信者本人が作成したこと（真正性）**」と「**改ざんされていないこと（完全性）**」を証明する仕組みです。暗号化とは鍵の使い方が **逆** になります。

### PKI（公開鍵基盤）とデジタル証明書

公開鍵暗号には「その公開鍵は本当に本人のものか？」という問題があります。これを解決するのが **PKI** です。

- **認証局（CA）**：公開鍵とその持ち主の対応を証明する、信頼できる第三者機関。
- **デジタル証明書（公開鍵証明書）**：認証局が、利用者の公開鍵と身元情報に **認証局のデジタル署名** を付けて発行したもの。標準規格は **X.509**。
- **CRL（証明書失効リスト）**：有効期限前に失効した証明書の一覧。秘密鍵の漏えい時などに失効させる。リアルタイムに失効状態を確認するプロトコルは **OCSP**。
- **ルート証明書**：最上位の認証局が自分自身で署名した証明書。ブラウザやOSにあらかじめ組み込まれている。

### TLS（SSL）

**TLS** は、Web などの通信を暗号化するプロトコルです（HTTPS は HTTP ＋ TLS）。サーバ証明書でサーバの正当性を確認し、ハイブリッド暗号方式で通信を暗号化し、MAC で改ざんを検知します。

## 4. 認証技術

### 利用者認証の3要素

| 要素 | 例 |
|---|---|
| **知識情報**（知っているもの） | パスワード、暗証番号、秘密の質問 |
| **所持情報**（持っているもの） | ICカード、スマートフォン、ワンタイムパスワード生成器 |
| **生体情報**（本人の身体的特徴） | 指紋、静脈、顔、虹彩、声紋 |

- **多要素認証**：異なる要素を **2つ以上** 組み合わせる認証。パスワード＋スマホへのコードなど。（パスワード＋秘密の質問は、同じ知識情報なので多要素ではない）
- **ワンタイムパスワード**：1回限り有効なパスワード。盗まれても再利用できない。
- **チャレンジレスポンス認証**：サーバが送るランダムな値（チャレンジ）とパスワードからハッシュ値（レスポンス）を作って返す。パスワードそのものがネットワークを流れない。
- **シングルサインオン（SSO）**：1回の認証で、複数のシステムを利用できる。**SAML**、**OpenID Connect** などの仕組みがある。
- **生体認証の誤り**：本人を拒否してしまう **本人拒否率（FRR）** と、他人を受け入れてしまう **他人受入率（FAR）** はトレードオフの関係。
- **FIDO（パスキー）**：パスワードを使わず、端末内の秘密鍵と生体認証などで認証する。サーバには公開鍵だけを登録するので、サーバから漏えいしても安全。
- **CAPTCHA**：ゆがんだ文字の読取りなどで、操作しているのが人間かプログラムかを判別する。

| **VPN** | インターネット上に、暗号化された仮想的な専用線を作る（**IPsec**、TLS） |
| **プロキシサーバ** | 内部の端末に代わってインターネットにアクセスする。通信の記録・フィルタリング |
| **検疫ネットワーク** | 社内LANに接続する端末を一時的に隔離し、セキュリティ状態（パッチ適用など）を検査してから接続を許可する |
| **UTM** | ファイアウォール・IPS・ウイルス対策などを1台にまとめた機器 |
| **EDR** | 端末（エンドポイント）の挙動を監視し、侵入後の不審な動きを検知・対応する |
| **SIEM** | 様々な機器のログを集めて相関分析し、攻撃の兆候を見つける |
| **ゼロトラスト** | 「社内なら安全」という境界防御の考えを捨て、**すべてのアクセスを信頼せずに毎回検証** する考え方 |

### メールのセキュリティ

- **SPF**：送信元メールサーバの IPアドレスを DNS に登録し、受信側で **送信元ドメインが詐称されていないか** を確認する。
- **DKIM**：送信側のメールサーバがメールに **デジタル署名** を付け、受信側が DNS の公開鍵で検証する。
- **DMARC**：SPF・DKIM の認証に失敗したメールをどう扱うか（受信拒否など）を、送信ドメインの管理者が宣言する。
- **OP25B（Outbound Port 25 Blocking）**：ISP が、自社ネットワーク内から外部のメールサーバの25番ポートへの直接の通信を遮断し、迷惑メールの送信を防ぐ。

### 無線 LAN・物理的な対策

- 無線LANの暗号化は **WPA3**（WPA2）を使い、WEPは使わない。
- **入退室管理**：ICカード、生体認証。**アンチパスバック**（入室記録がないと退室できない）、**共連れ防止**（1人の認証で複数人が通るのを防ぐ）。
- **クリアデスク・クリアスクリーン**：離席時に書類を机に放置しない、画面をロックする。

### 脆弱性への対策

- **セキュアプログラミング**：入力値の検証、エスケープ処理など、脆弱性を作らない書き方をする。
- **ペネトレーションテスト**：攻撃者の視点で実際にシステムに侵入を試み、脆弱性を確認する。
- **ファジング**：大量の異常なデータを入力して、未知の脆弱性を発見する。
- **CVSS**：脆弱性の深刻度を、ベンダーに依存しない共通の基準で0.0〜10.0の数値で評価する。
- **ディジタルフォレンジックス**：不正アクセスなどの事件が起きたとき、証拠となるデータを保全・解析する技術。
- **サンドボックス**：隔離された仮想環境で不審なプログラムを実行し、挙動を観察する。

## 6. セキュリティ管理

- **ISMS（情報セキュリティマネジメントシステム）**：組織として情報セキュリティを管理する仕組み。**JIS Q 27001** で要求事項が定められ、**PDCAサイクル**（Plan・Do・Check・Act）で継続的に改善する。
- **情報セキュリティポリシー**：組織のセキュリティに関する方針。**基本方針**（経営者の宣言）→ **対策基準**（何をすべきか）→ **実施手順**（具体的な手順）の3階層。
- **CSIRT**：セキュリティインシデント（事故）に対応する組織内のチーム。
- **SOC**：ネットワークやシステムを24時間監視し、攻撃を検知・分析する組織。
- **サイバーセキュリティ経営ガイドライン**：経済産業省とIPAが策定した、経営者が主導してサイバーセキュリティ対策を進めるための指針。
- **NOTICE、J-CRAT、J-CSIP** など：国や IPA によるサイバー攻撃対策の取組み。

## 7. 過去問（令和2〜6年度）で問われた発展テーマ

### 追加の攻撃手法

| 攻撃・用語 | 内容 |
|---|---|
| **クリプトジャッキング** | 他人の PC やサーバにマルウェアを感染させ、その **CPU などの資源を無断で使って暗号資産をマイニング（採掘）** させる |
| **サイドチャネル攻撃** | 暗号処理中の **消費電力・処理時間・電磁波** などの物理的な情報を測定し、そこから秘密鍵を推測する |
| **ダークネット** | インターネット上で **使われていない IP アドレス空間**。本来は通信が届かないはずなので、届くパケットはマルウェアの感染活動（スキャン）や、送信元を偽装した DDoS 攻撃の跳ね返り（バックスキャッタ）と考えられ、攻撃の観測に使われる |
| **DNSキャッシュポイズニング** | キャッシュ DNS サーバに偽の応答を覚えさせる。対策は、問合せの **送信元ポート番号をランダム化** すること、**DNSSEC** を使うこと |
| **スミッシング** | SMS（ショートメッセージ）を使ったフィッシング |
| **ドライブバイダウンロード** | Web サイトを **閲覧しただけ** で、利用者が気づかないうちにマルウェアをダウンロード・実行させる |
| **パスワードスプレー攻撃** | よく使われるパスワードを1つ決め、多数のアカウントに対して少しずつ試す（ロックされにくい） |

### パスワードの安全な保存（令和6年度秋期 午後問1）

サーバにパスワードをそのまま（平文で）保存すると、漏えいしたときにすぐ悪用されます。そこで次のように保存します。

- **ハッシュ化**：パスワードのハッシュ値だけを保存する。ログイン時は、入力されたパスワードのハッシュ値と比べる。ハッシュ値から元のパスワードは計算できない。
- **ソルト**：利用者ごとに異なるランダムな値（ソルト）をパスワードに付け加えてからハッシュ化する。**同じパスワードでも異なるハッシュ値** になり、レインボーテーブル攻撃を防げる。
- **ストレッチング**：ハッシュ計算を **何千回も繰り返す**。1回の計算に時間がかかるので、総当たり攻撃にかかる時間を大幅に増やせる。

### 認証の補足

- **リスクベース認証**：普段と異なる環境（いつもと違う国や端末、IPアドレス）からのログインのときだけ、**追加の認証** を求める。
- **SAML**：シングルサインオンを実現する規格。利用者を認証する **IdP（アイデンティティプロバイダ）** が、認証結果（**アサーション**）を XML で発行し、サービスを提供する **SP（サービスプロバイダ）** がそれを信頼してログインを許可する。流れは「SP にアクセス → IdP にリダイレクト → IdP で認証 → アサーションを持って SP へ → 利用開始」。
- **OAuth 2.0**：利用者のパスワードを渡さずに、あるサービスが別のサービスのデータにアクセスする **権限（アクセストークン）** を与える仕組み（認可）。
- **TLS のクライアント認証**：サーバがクライアントにも証明書を要求し、クライアントは自分の秘密鍵で署名したデータとクライアント証明書を送る。サーバはその証明書の公開鍵で署名を検証する。
- **3-D セキュア**：インターネットでのクレジットカード決済で、カード会社が **本人であることを追加で確認** する仕組み（パスワードやワンタイムパスワード、リスクベース認証）。盗まれたカード番号だけでは決済できなくなる。
- **IEEE 802.1X**：LAN に接続する端末を、認証サーバ（**RADIUS**）で認証してから接続を許可する。

### 機器・OSの保護

| 技術 | 内容 |
|---|---|
| **耐タンパ性** | 内部の情報を外部から不正に読み取られにくい性質。例えば **IC カード** は、チップを開封したり異常な電圧をかけたりすると内部のデータを消去する仕組みを持つ |
| **TPM** | PC などに搭載された、耐タンパ性を持つセキュリティチップ。**鍵の生成・保管**、暗号処理、起動時のソフトウェアの改ざん検知などを行う |
| **HSM** | 暗号鍵を安全に生成・保管し、暗号処理を行う専用のハードウェア装置 |
| **セキュアブート** | PC の起動時に、OS やブートローダの **デジタル署名を検証** し、改ざんされていない正しいものだけを起動する |
| **セキュアOS** | **強制アクセス制御**（管理者でも決められた権限を超えられない）と **最小特権** を実現する OS。侵入されても被害を最小限にできる |

### メール・通信の暗号化

- **PPAP の問題点**（令和5年度秋期 午後問1）：パスワード付き ZIP ファイルをメールで送り、パスワードを **別のメールで同じ経路で** 送る方式。経路を盗聴されれば両方とも漏れる、ZIP の中身をウイルス対策ソフトで検査できない、などの問題がある。代わりに **S/MIME**（メール自体の暗号化と署名）や、クラウドストレージでの共有を使う。
- **POP3S・IMAPS**：POP3・IMAP の通信を TLS で暗号化したもの。スマートフォンでメールを受信するときの盗聴を防ぐ。
- **IPsec**：ネットワーク層で通信を暗号化するプロトコル。**AH**（認証ヘッダ：改ざん検知）と **ESP**（暗号ペイロード：暗号化）がある。VPN で使われる。
- **DNSSEC**：DNS の応答に **デジタル署名** を付け、受け取った側が署名を検証することで、応答が改ざんされていないこと（正しい権威DNSサーバからの応答であること）を確認できる。
- **Cookie の属性**：**Secure**（HTTPS 通信のときだけ送信する）、**HttpOnly**（JavaScript から読み取れないようにする → XSS による盗取を防ぐ）、**SameSite**（別のサイトからのリクエストに Cookie を付けない → CSRF 対策）。
- **公衆無線LANの対策**：**プライバシーセパレータ**（同じアクセスポイントにつながった端末どうしの通信を禁止する）、WPA3 による暗号化。

### ゼロトラストを実現する技術（令和6年度春期 午後問1）

| 技術 | 内容 |
|---|---|
| **IDaaS** | クラウドで ID 管理と認証（シングルサインオン、多要素認証）を提供するサービス |
| **SWG（セキュアWebゲートウェイ）** | クラウド型のプロキシ。社外からのアクセスも含め、Web 通信の URL フィルタリングやマルウェア検査を行う |
| **CASB** | 社員のクラウドサービス利用を **可視化・制御** する（許可していないクラウドサービス＝シャドーITの検出など） |
| **MDM** | 会社が支給したスマートフォンなどを一元管理し、紛失時に遠隔でロック・データ消去する |
| **SASE** | ネットワーク機能（VPN など）とセキュリティ機能（SWG、CASB など）をクラウドで統合して提供する考え方 |

### 内部不正対策（令和2年度 午後問1）

- **不正のトライアングル**：不正は「**動機**（金銭的な困窮など）」「**機会**（不正ができる環境）」「**正当化**（自分を納得させる理由）」の3つがそろったときに起きやすい。
- **状況的犯罪予防**：IPA の「組織における内部不正防止ガイドライン」では、①犯行を **難しく** する（アクセス制限）、②**見つかりやすく** する（ログの監視）、③**割に合わなく** する、④その気にさせない、⑤言い訳を許さない、の5つの観点で対策を立てる。

### 脆弱性情報の流通と関連組織

- **CVE**：個々の脆弱性に付けられる **共通の識別番号**（CVE-2024-12345 など）。
- **CWE**：脆弱性の **種類**（SQLインジェクション、バッファオーバーフローなど）を分類した共通の体系。
- **CVSS**：脆弱性の深刻度の評価。**基本評価基準**（脆弱性そのものの特性）・**現状評価基準**（攻撃コードの有無など、時間とともに変わる）・**環境評価基準**（利用者の環境での影響）の3つで評価する。
- **JPCERT/CC**：日本のインシデント対応の支援や、脆弱性情報の調整を行う組織。特定の政府機関や企業から独立した中立の組織。
- **情報セキュリティ早期警戒パートナーシップ**：ソフトウェアの脆弱性を発見した人が **IPA に届け出** → **JPCERT/CC が製品開発者と調整** → 対策が整ったら **JVN**（脆弱性対策情報ポータルサイト）で公表する、という日本の制度。
- **SBOM**：ソフトウェアを構成する部品（ライブラリなど）の一覧。脆弱性が見つかったときに影響範囲をすぐ特定できる。

### インシデント対応とフォレンジックス

- **インシデント対応の流れ**：検知・報告 → トリアージ（優先順位付け） → 封じ込め（ネットワークからの切り離しなど） → 根絶 → 復旧 → 事後対応（再発防止）。
- **ディジタルフォレンジックスの手順**：**収集 → 検査 → 分析 → 報告**。収集時には証拠の **ハッシュ値** を記録し、後で改ざんされていないことを証明できるようにする（証拠保全）。
- **ハニーポット**：わざと攻撃されやすいように見せたおとりのシステム。攻撃手法の観察・研究に使う。

### マネジメント規格の用語

- **JIS Q 27000（ISMS の用語）**：「**リスクレベル**」は結果とその起こりやすさの組合せで表される、リスクの大きさ。「**否認防止**」「**真正性**」などの用語もこの規格で定義されている。
- **JIS Q 31000（リスクマネジメント）**：あらゆる組織のリスクマネジメントの指針。リスク特定では、有形・無形の原因、機会と脅威、変化の兆候などを考慮する。
- **IoT セキュリティガイドライン**：IoT 機器・サービスの方針・分析・設計・構築・運用の各段階で取るべき対策をまとめた指針。
- **制御システムのセキュリティ**：工場の制御ネットワークと情報（事務）ネットワークの間にファイアウォールを置き、通信を必要最小限に制限する。
