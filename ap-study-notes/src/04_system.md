## 1. システムの処理形態と構成

### 処理形態

- **集中処理**：1台の大型コンピュータ（ホスト）ですべてを処理する。管理しやすいが、ホストが止まると全体が止まる。
- **分散処理**：複数のコンピュータで処理を分担する。一部が止まっても全体は動き続けられるが、管理が複雑。
- **クライアントサーバシステム**：サービスを要求する側（クライアント）と提供する側（サーバ）に役割を分ける。
- **3層クライアントサーバ**：**プレゼンテーション層**（画面）、**ファンクション層**（業務処理）、**データ層**（データベース）の3つに分ける。各層を独立して変更しやすい。
- **ピアツーピア（P2P）**：対等なコンピュータどうしが直接やり取りする。

### 冗長化構成（高信頼化）

| 構成 | しくみ |
|---|---|
| **デュアルシステム** | 2系統のシステムで **同じ処理を同時に** 行い、結果を照合する。片方が故障してもすぐ処理を続けられる |
| **デュプレックスシステム** | 主系（現用系）と従系（待機系）を用意し、主系が故障したら従系に切り替える |
| ホットスタンバイ | 待機系を起動した状態で待たせる。切替えが速い |
| コールドスタンバイ | 待機系を停止した状態で待たせる。切替えに時間がかかるが安価 |
| **クラスタ** | 複数のサーバを連携させて、1台のように見せる。負荷分散や高可用性を実現 |
| **ロードバランサ** | 複数のサーバに処理要求を振り分ける装置 |

### クラウドコンピューティング

インターネット経由で、サーバやソフトウェアを「サービス」として利用する形態です。利用者は必要な分だけ借りて、使った分だけ支払います。

- **パブリッククラウド**：不特定多数で共有する。**プライベートクラウド**：自社専用。**ハイブリッドクラウド**：両者の組合せ。
- **オンプレミス**：自社内に機器を設置して運用する従来の形態。
- **エッジコンピューティング**：データの発生源（端末）の近くで処理し、通信の遅延や量を減らす。IoTで重要。

### 仮想化

**仮想化** とは、1台の物理的なコンピュータの上で、複数の論理的な（仮想の）コンピュータを動かす技術です。

| 方式 | しくみ |
|---|---|
| **ホスト型** | ホストOSの上に仮想化ソフトを入れ、その上でゲストOSを動かす |
| **ハイパーバイザ型** | ハードウェアの上に直接ハイパーバイザ（仮想化ソフト）を置き、その上でゲストOSを動かす。オーバーヘッドが小さい |
| **コンテナ型** | 1つのOSの上で、アプリケーションの実行環境を隔離した「コンテナ」を複数動かす。ゲストOSが不要なので軽量・高速に起動する（Dockerなど） |

- **ライブマイグレーション**：仮想マシンを **停止させずに** 別の物理サーバへ移動させる技術。
- **VDI（デスクトップ仮想化）**：利用者のデスクトップ環境をサーバ上で動かし、端末には画面だけを転送する。端末にデータが残らないので情報漏えい対策になる。

### IaC（Infrastructure as Code）

**IaC** とは、サーバやネットワークなどの **インフラの構成・設定をプログラム（コード）として記述し、専用のソフトウェアがその内容に従って自動的にシステムに適用する** 考え方です。手作業による設定ミスを防ぎ、同じ環境を何度でも再現できます。コードなのでバージョン管理やレビューも可能です。

:::exam R7秋 午前問12
IaC の説明を選ぶ問題。「システムの構成、設定などをプログラムとして記述し、専用のソフトウェアがその内容に従って自動的にシステムに適用する」が正解。「手動で」という言葉が入った選択肢は誤りです。
:::

## 2. 信頼性 ― RASIS と稼働率

### RASIS（ラシス）

システムの信頼性を評価する5つの指標の頭文字です。

| 指標 | 意味 | 代表的な尺度 |
|---|---|---|
| **R**eliability（信頼性） | 故障しにくいこと | MTBF |
| **A**vailability（可用性） | 使いたいときに使えること | 稼働率 |
| **S**erviceability（保守性） | 故障してもすぐ直せること | MTTR |
| **I**ntegrity（完全性） | データが壊れたり矛盾したりしないこと | |
| **S**ecurity（安全性） | 不正アクセスから守られていること | |

### MTBF・MTTR・稼働率

<div class="cap" style="font-size:9.5pt;color:#173a63"><b>稼働率 ＝ MTBF ÷ (MTBF ＋ MTTR)</b>　（全体の時間のうち、動いている時間の割合）</div>
</div></div>

- **MTBF（Mean Time Between Failures：平均故障間隔）**：故障が直ってから次に故障するまでの平均時間。**長いほど良い**（信頼性）。
- **MTTR（Mean Time To Repair：平均修理時間）**：故障してから直るまでの平均時間。**短いほど良い**（保守性）。
- **故障率** ＝ 1 ÷ MTBF（単位時間あたりに故障する回数）。

:::calc 稼働率の計算
MTBF が 480時間、MTTR が 20時間のシステムの稼働率は？
稼働率 ＝ 480 ÷ (480 ＋ 20) ＝ 480 ÷ 500 ＝ **0.96**（96%）
:::

:::exam R7秋 午前問13
信頼性に関する記述として適切なものを選ぶ問題。「MTBF/(MTBF＋MTTR) はシステムが稼働している時間の割合を表す」が正解です。MTBF は「運用開始から初めて故障するまで」ではなく「故障間隔の平均」、MTTR は「修理にかかる時間の平均」です。
:::

<div class="tip"><b>考え方</b>　並列は「両方とも止まる確率」を1から引く。止まる確率 (1−a) を掛け合わせるのがコツです。</div>
</div></div>

:::calc 直列と並列の組合せ
稼働率 0.9 の装置2台を並列にしたものと、稼働率 0.95 の装置1台を直列につないだシステムの稼働率は？
**①並列部分**：1 − (1 − 0.9) × (1 − 0.9) ＝ 1 − 0.01 ＝ 0.99
**②直列**：0.99 × 0.95 ＝ **0.9405**
複雑な構成も「内側の並列を1つの装置とみなす → 直列で掛ける」と分解すれば解けます。
:::

:::note n台中 k台以上が動けばよいシステム
「3台中2台以上動けばよい」システムの稼働率は、「3台とも動く確率」＋「ちょうど2台動く確率」です。稼働率 a のとき a³ ＋ 3a²(1−a) ＝ 3a² − 2a³。組合せ（第1章）の考え方を使います。
:::

### 信頼性を高める設計の考え方

| 用語 | 意味 |
|---|---|
| **フォールトトレランス** | 故障が起きても、冗長化などによってシステム全体としては機能を維持する |
| **フェールセーフ** | 故障時には **安全側** に動作させる（信号機の故障時は全部赤にする） |
| **フェールソフト** | 故障した部分を切り離して、機能を縮小してでも動き続ける（縮退運転） |
| **フォールトアボイダンス** | 高品質の部品を使うなどして、そもそも故障しないようにする |
| **フールプルーフ** | 人が誤った操作をしても、危険な状態にならないようにする（ドアが閉まらないと動かない電子レンジ） |

:::point フェールセーフとフェールソフトの区別
フェール「セーフ」は **安全** 優先（止めてもよい）、フェール「ソフト」は **継続** 優先（性能を落としてでも動かす）。選択肢で頻繁に入れ替えて出題されます。
:::

### バスタブ曲線

装置の故障率は時間とともに「**初期故障期**（製造不良などで故障率が高い）→ **偶発故障期**（低く安定）→ **摩耗故障期**（劣化で上昇）」と変化し、グラフがお風呂の形になるので **バスタブ曲線** と呼ばれます。

## 3. 性能評価

### 性能の指標

- **レスポンスタイム（応答時間）**：要求を出してから、最初の応答が返ってくるまでの時間。
- **ターンアラウンドタイム**：ジョブを投入してから、すべての結果を受け取るまでの時間。
- **スループット**：単位時間あたりに処理できる仕事の量。

### 性能評価の手法

| 手法 | 内容 |
|---|---|
| **ベンチマーク** | 標準的なプログラムを実際に実行して、性能を測定・比較する（SPECなど） |
| **モニタリング** | 稼働中のシステムの資源使用状況や応答時間を測定する |
| **シミュレーション** | モデルを作って性能を予測する |
| TPC | トランザクション処理（OLTP）性能のベンチマーク |

### キャパシティプランニング

**キャパシティプランニング** とは、将来の利用者数やデータ量の増加を予測し、**将来にわたって必要なサービスレベル（応答時間など）を維持できるように**、システム資源の容量を計画することです。「現状を最大限引き出す」チューニングとは目的が違います。

:::exam R7秋 午前問14
キャパシティプランニングの目的に関する記述を選ぶ問題。「現在の応答時間を調査し、長期的に監視することで、**将来を含めて** 応答時間を維持する」が最も適切です。「現状の処理能力を最大限に引き出す」はチューニングの説明です。
:::

### スケールアップとスケールアウト

- **スケールアップ**：サーバ1台の性能を上げる（CPUやメモリの増強）。
- **スケールアウト**：サーバの **台数を増やして** 処理を分散する。Webサーバやクラウドで多用。
- **スケールダウン／スケールイン**：それぞれの逆（性能を下げる／台数を減らす）。

## 4. 過去問（令和2〜6年度）で問われた発展テーマ

### 様々なシステム形態

| 用語 | 内容 |
|---|---|
| **グリッドコンピューティング** | ネットワーク上の多数のコンピュータを結び付け、**1つの高性能な仮想コンピュータ** として大規模な計算を行う |
| **Hadoop** | 大量のデータを **多数のサーバで分散処理** するための OSS のフレームワーク（分散ファイルシステム HDFS と、分散処理の MapReduce） |
| **サーバレス（FaaS）** | 利用者はサーバを意識せず、処理（関数）だけを用意する。イベントが発生したときだけ実行され、実行した分だけ料金がかかる |
| **ハイパーコンバージドインフラ（HCI）** | サーバにストレージの機能を統合し、仮想化ソフトウェアで一元管理する構成 |
| **シンクライアント** | 端末には最低限の機能だけを持たせ、処理やデータはサーバ側で管理する |

### ストレージの種類

| 方式 | 内容 |
|---|---|
| **ブロックストレージ** | データを固定長のブロック単位で扱う。高速で、データベースなどに向く（SAN） |
| **ファイルストレージ** | フォルダとファイルの階層構造で扱う。ファイル共有に向く（NAS） |
| **オブジェクトストレージ** | データを、データ本体・**メタデータ**・一意の ID を持つ「オブジェクト」として、**階層を持たないフラットな空間** で管理する。HTTP（REST API）でアクセスし、画像・動画・ログなど **大量の非構造化データ** の保存に向く。クラウドのストレージサービスで広く使われる |

- **NAS**：LAN に直接接続するファイルサーバ専用機。**SAN**：サーバとストレージを専用の高速ネットワークで接続する。

### 冗長化構成の補足

- **ハートビート**：クラスタ構成で、待機系が現用系に定期的に信号を送り合って **生きているかを監視** する仕組み。現用系からの応答が途絶えたことを契機に、待機系に切り替える（**フェールオーバ**）。
- **フェールバック**：障害が復旧した後、元の現用系に処理を戻すこと。
- **アクティブ／アクティブ構成**：2台とも稼働させて負荷を分散する。**アクティブ／スタンバイ構成**：1台は待機する。
- **MTTR を短くする機能**：エラーログの取得、遠隔保守、自己診断機能など（故障を早く見つけて直すため）。**MTBF を長くする**：高品質な部品、冗長化など。

### 性能の計算

:::calc CPU 使用率
1件のトランザクションで CPU を 20 ミリ秒使う。ピーク時には1秒間に 30 件のトランザクションが発生する。CPU 使用率は？
1秒間に使う CPU 時間 ＝ 20ms × 30件 ＝ 600ms ＝ 0.6秒 → CPU 使用率 ＝ 0.6 ÷ 1 ＝ **60%**
:::

:::calc スケールアウトで必要な台数
1台のサーバで1秒間に 200 件処理でき、CPU 使用率を 70% 以下に抑えたい。ピーク時に1秒間 1,000 件の要求があるとき、必要な台数は？
1台で処理させてよい件数 ＝ 200 × 0.7 ＝ 140件 → 1,000 ÷ 140 ≒ 7.1 → **8台**（切り上げ）
:::

- **密結合マルチプロセッサの性能低下**：プロセッサ数を増やしても、主記憶などの **共有資源の競合** や、プロセッサ間の調整（排他制御）のオーバーヘッドで、性能は台数倍にならない。

:::sum
- IaaS（インフラ）→ PaaS（実行環境）→ SaaS（アプリ）の順に事業者の管理範囲が広がる。
- コンテナはゲストOS不要で軽量。IaC は構成をコードで書き、自動で適用する。
- 稼働率 ＝ MTBF ÷ (MTBF＋MTTR)。直列は掛け算、並列は 1 − (1−a)(1−b)。
- フェールセーフ＝安全側、フェールソフト＝縮退して継続、フールプルーフ＝誤操作対策。
- キャパシティプランニングは「将来の需要」に対する容量計画。スケールアウトは台数増。
:::
