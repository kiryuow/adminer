## 1. プログラムの基本要素

### 変数・代入・データ型

- **変数**：データを入れておく名前付きの箱。「x ← 5」は「xに5を入れる（代入する）」という意味（試験の擬似言語では ← を使う）。
- **データ型**：変数に入るデータの種類。整数型、実数型、文字型、論理型（true/false）など。
- **定数**：値を変えない名前付きのデータ。

### 制御構造（構造化プログラミング）

どんなアルゴリズムも、次の3つの組合せで書けます（**構造化定理**）。

<div class="fig"><div class="fig-t">3つの基本構造</div><div class="fig-b">
<div class="cards" style="--n:3">
<div class="card c1"><b>順次</b>上から順に1つずつ実行する</div>
<div class="card c2"><b>選択（分岐）</b>条件によって実行する処理を変える（if 〜 else）</div>
<div class="card c4"><b>繰返し（ループ）</b>条件を満たす間、同じ処理を繰り返す（while, for）</div>
</div></div></div>

:::note 擬似言語の読み方
試験では特定のプログラム言語ではなく、IPA独自の **擬似言語** で書かれたプログラムが出ます。「if 〜 elseif 〜 else 〜 endif」「while (条件) 〜 endwhile」「for (i を 1 から n まで 1 ずつ増やす) 〜 endfor」のような日本語混じりの書き方です。配列の添字は **1から始まる** 場合が多いので、問題文の注記を必ず確認しましょう。
:::

### トレース（追跡）

プログラムを1行ずつ実行したつもりで、変数の値の変化を表に書き出していく作業を **トレース** といいます。午後のプログラミング問題では、トレースが最も確実な武器です。

:::calc 合計を求めるプログラムをトレースする
```
sum ← 0
for (i を 1 から 4 まで 1 ずつ増やす)
    sum ← sum + i
endfor
```
| 繰返し | i | sum（実行後） |
|---|---|---|
| 1回目 | 1 | 1 |
| 2回目 | 2 | 3 |
| 3回目 | 3 | 6 |
| 4回目 | 4 | 10 |
:::

## 2. 基本的なデータ構造

### 配列

**配列** は、同じ型のデータを連続した領域に並べたものです。**添字（インデックス）** で何番目の要素かを指定して、直接アクセスできます。

- 長所：添字を指定すれば、何番目の要素でも **すぐに読み書きできる**。
- 短所：途中に要素を挿入・削除すると、**後ろの要素を全部ずらす** 必要があり遅い。
- **2次元配列**：行と列で表す表のような配列。メモリ上では1列に並べて格納する（行ごとに並べる「行優先」など）。

### リスト（連結リスト）

**リスト** は、各要素（ノード）が「データ」と「次の要素の場所（**ポインタ**）」を持ち、ポインタで数珠つなぎにしたデータ構造です。

- **単方向リスト**：次の要素へのポインタだけを持つ。
- **双方向リスト**：次と前の両方のポインタを持つ。逆向きにもたどれる。
- **循環リスト**：最後の要素が先頭を指す。
- 長所：挿入・削除は **ポインタの付け替えだけ** で済み、データの移動が不要。短所：n番目の要素を見るには **先頭から順にたどる** 必要がある。

### 木構造

**木（ツリー）** は、データを親子関係で階層的に表すデータ構造です。一番上を **根（ルート）**、子を持たない末端を **葉（リーフ）**、各要素を **節（ノード）** と呼びます。

- **2分木**：各ノードの子が最大2つの木。
- **完全2分木**：葉以外のすべての段が埋まっていて、最下段は左から詰まっている2分木。
- **2分探索木**：「左の子孫 ＜ 親 ＜ 右の子孫」というルールを満たす2分木。探索が速い。
- **ヒープ**：「親 ≧ 子」（または「親 ≦ 子」）のルールを満たす完全2分木。根が常に最大（最小）値になる。優先度付きキューやヒープソートに使う。
- **バランス木（B木など）**：木の高さが偏らないように調整する木。データベースの索引（インデックス）に使われる。

:::note 木のなぞり方（走査）
**行きがけ順（先行順）**：親 → 左 → 右　／　**通りがけ順（中間順）**：左 → 親 → 右　／　**帰りがけ順（後行順）**：左 → 右 → 親。2分探索木を通りがけ順でなぞると、データが **小さい順** に取り出せます。数式の木を帰りがけ順でなぞると逆ポーランド記法になります。
:::

### グラフ

点（**頂点・ノード**）と、それらを結ぶ線（**辺・エッジ**）で表したデータ構造です。道路網やネットワークの経路をモデル化します。辺に向きがあるものを **有向グラフ**、重み（距離・コスト）があるものを **重み付きグラフ** といいます。最短経路を求める **ダイクストラ法** が代表的なアルゴリズムです。

## 3. 探索アルゴリズム

**探索** とは、たくさんのデータの中から目的のデータを探し出すことです。

| 方式 | 方法 | 前提条件 | 平均比較回数 | 計算量 |
|---|---|---|---|---|
| **線形探索** | 先頭から順に1つずつ比べる | なし | 約 n/2 回 | O(n) |
| **二分探索** | 真ん中と比べ、探す範囲を半分ずつに絞る | **データが整列済み** | 約 log<sub>2</sub>n 回 | O(log n) |
| **ハッシュ探索** | ハッシュ関数でデータの格納位置を計算し、直接アクセスする | ハッシュ表に格納済み | 原則1回 | O(1) |

:::calc 二分探索の最大比較回数
1,000個の整列済みデータを二分探索するとき、最大何回比べれば見つかる？
1回比べるごとに範囲が半分 → 2<sup>10</sup> ＝ 1024 ≧ 1000 なので、**最大約10回**（正確には ⌊log<sub>2</sub>n⌋＋1 回）。線形探索なら最大1,000回なので、圧倒的に速い。
:::

:::note ハッシュの衝突（シノニム）
異なるデータから同じハッシュ値（格納位置）が計算されてしまうことを **衝突（コリジョン）** といい、衝突したデータどうしを **シノニム** といいます。対策には、次の空き場所に入れる **オープンアドレス法** と、同じ位置のデータをリストでつなぐ **チェイン法** があります。
:::

:::exam R7秋 午前問6
整列済みの表を m 個ずつのブロックに分け、まず各ブロックの最後尾だけを線形探索してブロックを特定し、次にブロック内を線形探索する方式の平均比較回数を問う問題。ブロック数は n/m 個なので1段目の平均は約 (n/m)/2 回、2段目はブロック内 m 個の平均で約 m/2 回、合計で **m/2 ＋ n/(2m)** となります。「線形探索の平均比較回数は個数の半分」を2回使うだけです。
:::

## 4. 整列（ソート）アルゴリズム

**整列（ソート）** とは、データを小さい順（昇順）や大きい順（降順）に並べ替えることです。

<div class="fig" markdown="1"><div class="fig-t">第2章③ 代表的な整列アルゴリズム<small>上の3つは単純だが遅い O(n²)、下の3つは速い O(n log n)</small></div><div class="fig-b" markdown="1">

| 名前 | しくみ | 平均計算量 | 最悪 |
|---|---|---|---|
| **バブルソート** | 隣どうしを比べて、逆順なら交換する。大きい値が泡のように後ろへ浮かぶ | O(n²) | O(n²) |
| **選択ソート** | 未整列部分から最小値を **選んで** 先頭と交換する | O(n²) | O(n²) |
| **挿入ソート** | 未整列部分の先頭を、整列済み部分の適切な位置に **挿入** する。ほぼ整列済みのデータに強い | O(n²) | O(n²) |
| **クイックソート** | 基準値（ピボット）より小さいグループと大きいグループに分け、それぞれを再帰的に整列する。平均的に最速 | O(n log n) | O(n²) |
| **マージソート** | データを半分ずつに分割し続け、整列しながら併合（マージ）する | O(n log n) | O(n log n) |
| **ヒープソート** | データをヒープにし、根（最大値）を取り出すことを繰り返す | O(n log n) | O(n log n) |
| **シェルソート** | 一定間隔ごとに挿入ソートを行い、間隔を狭めていく（挿入ソートの改良） | 約O(n<sup>1.25</sup>) | O(n²) |

</div></div>

:::calc バブルソートを1周だけトレースする
[5, 3, 8, 1] を昇順に。隣どうしを左から比べて、左が大きければ交換する。
(5,3)交換 → [3,5,8,1]　(5,8)そのまま → [3,5,8,1]　(8,1)交換 → [3,5,1,**8**]
1周目で最大値8が一番右に確定しました。これを残りの要素で繰り返します。
:::

## 5. 計算量（オーダー記法）

**計算量** は、データ量 n が増えたときに、処理時間がどのくらいの勢いで増えるかを表す目安です。**O（オーダー）記法** で書き、最も影響の大きい項だけを残し、係数は無視します（例：3n² ＋ 5n → O(n²)）。

| 計算量 | n が 2倍になると | 例 |
|---|---|---|
| O(1) | 変わらない | ハッシュ探索、配列の添字アクセス |
| O(log n) | 1回分増えるだけ | 二分探索 |
| O(n) | 2倍 | 線形探索 |
| O(n log n) | 2倍強 | クイックソート、マージソート |
| O(n²) | 4倍 | バブル・選択・挿入ソート（二重ループ） |
| O(2<sup>n</sup>) | 爆発的に増える | 全組合せの総当たり |

:::point ループの形で計算量がわかる
1重ループ → O(n)、二重ループ → O(n²)、毎回半分にする → O(log n)。午後問題で「この処理の計算量は？」と聞かれたら、まずループの入れ子の深さを見ましょう。
:::

## 6. 再帰

**再帰** とは、関数（手続）の中で **自分自身を呼び出す** ことです。大きな問題を「同じ形の小さな問題」に分けて解くときに使います。必ず「これ以上呼び出さずに答えを返す条件（終了条件）」を書きます。

:::calc 階乗を再帰で計算する
```
○整数型: fact(整数型: n)
  if (n = 0)
    return 1                // 終了条件
  else
    return n × fact(n − 1)  // 自分自身を呼び出す
  endif
```
fact(3) ＝ 3 × fact(2) ＝ 3 × 2 × fact(1) ＝ 3 × 2 × 1 × fact(0) ＝ 3 × 2 × 1 × 1 ＝ **6**
呼出しのたびに戻り先がスタックに積まれ、終了条件に達してから逆順に計算が戻ってきます。
:::

- **再入可能（リエントラント）**：複数のプロセスから同時に呼ばれても正しく動くプログラム。データを呼出しごとに別の領域（スタックなど）に持つ。
- **再帰的**：自分自身を呼び出せるプログラム。
- **再使用可能（リユーザブル）**：一度実行した後、ロードし直さずに再実行できるプログラム。

## 7. プログラム言語とマークアップ言語

### 言語処理の方式

- **コンパイラ**：ソースコード全体をまとめて機械語に翻訳してから実行する。実行が速い（C、C++、Goなど）。
- **インタプリタ**：ソースコードを1行ずつ解釈しながら実行する。手軽だが遅め（Python、JavaScriptなど）。
- **JIT（実行時）コンパイル**：中間コードを実行時に機械語に変換して高速化する（Java、C#など）。

### プログラム言語の特徴（頻出）

| 言語 | 特徴 |
|---|---|
| **Java** | オブジェクト指向。中間コード（バイトコード）をJVM上で実行するので、OSに依存しない |
| **Python** | 動的型付けのインタプリタ言語。AI・データ分析で広く利用 |
| **JavaScript** | Webブラウザ上で動くスクリプト言語。Node.jsでサーバ側でも動く |
| **Scala** | **オブジェクト指向と関数型の両方** のプログラミングが可能。JVM上で動作し、静的型付け |
| **Kotlin** | JVM上で動作。Androidアプリ開発の公式言語 |
| **R** | 統計解析・グラフ描画向けの言語 |
| **Rust** | メモリ安全性を重視したシステムプログラミング言語 |
| **C** | OSや組込み機器の開発に使われる手続き型言語 |

:::exam R7秋 午前問7
OSS として公開されている言語 Scala の特徴を問う問題。「オブジェクト指向プログラミングと関数型プログラミングの両方が可能」が正解です。多重継承や動的型付けではない点に注意します。
:::

### マークアップ言語・データ記述言語

- **HTML**：Webページの構造を記述する。
- **XML**：タグを自由に定義できる。データ交換に使う。
- **JSON**：JavaScriptのオブジェクト表記を基にした、軽量なデータ記述形式。`{"name": "山田", "age": 30}` のように書く。Web API で標準的に使われる。
- **YAML**：インデントで構造を表す、人間が読みやすいデータ記述形式。設定ファイルに多用される。

## 8. グラフと木の応用アルゴリズム（午後問3の頻出テーマ）

### 深さ優先探索と幅優先探索

グラフや木のすべての頂点を調べる（**探索する**）方法には、大きく2種類あります。

<div class="fig"><div class="fig-t">第2章④ 深さ優先探索と幅優先探索</div><div class="fig-b"><div class="two">
<div class="card c3"><b>深さ優先探索（DFS）</b>行けるところまで深く進み、行き止まりになったら1つ戻って（<b style="display:inline">バックトラック</b>）別の道を進む。<br><b style="display:inline">スタック</b> または <b style="display:inline">再帰</b> で実装する。<br>用途：迷路の解、パズルの全解探索、一筆書き</div>
<div class="card c2"><b>幅優先探索（BFS）</b>出発点から近い順（1歩で行ける所 → 2歩で行ける所 …）に、同じ深さの頂点を全部調べてから次の深さに進む。<br><b style="display:inline">キュー</b> で実装する。<br>用途：辺の重みがない場合の最短経路（最小手数）</div>
</div></div></div>

:::calc 探索順序の違い
根 A の子が B・C、B の子が D・E、C の子が F の木を、左の子から順に探索する。
**深さ優先**：A → B → D → E → C → F（Bの下を全部調べてから C へ）
**幅優先**：A → B → C → D → E → F（深さ1の B・C を調べてから深さ2へ）
:::

:::note 迷路を再帰で解く考え方
「現在のマスから上下左右に進めるなら、そのマスに印を付けて同じ処理を呼び出す。ゴールに着いたら終了、どこにも進めなければ印を消して戻る」という処理を再帰で書くのが定番です。迷路は **2次元配列**（壁＝1、通路＝0 など）で表し、訪問済みの印で同じマスを二度調べないようにします。
:::

### ダイクストラ法（最短経路）

**ダイクストラ法** は、辺に距離（重み）があるグラフで、出発点から各頂点までの **最短距離** を求めるアルゴリズムです。辺の重みが負でないことが条件です。

:::how ダイクストラ法の手順
**①** 出発点の距離を0、他の頂点の距離を∞（未定）とする。
**②** 距離が確定していない頂点のうち、**距離が最小の頂点** を選んで確定する。
**③** 確定した頂点から辺でつながる頂点について、「確定した頂点の距離 ＋ 辺の重み」が今の値より小さければ書き換える。
**④** すべての頂点が確定するまで②③を繰り返す。
:::

:::calc ダイクストラ法を手で解く
辺：S→A 2、S→B 5、A→B 1、A→C 6、B→C 2。S から C への最短距離は？
・S を確定（0）。A＝2、B＝5 に更新。
・未確定で最小の A（2）を確定。B は 2＋1＝3 ＜ 5 なので 3 に、C は 2＋6＝8 に更新。
・最小の B（3）を確定。C は 3＋2＝5 ＜ 8 なので 5 に更新。
・C（5）を確定。最短経路は S → A → B → C で **5**。
:::

### 動的計画法

**動的計画法** は、大きな問題を小さな部分問題に分け、**部分問題の答えを表（配列）に記録して再利用する** ことで、同じ計算の繰返しを避ける手法です。再帰で素直に書くと何度も同じ計算をしてしまう問題（フィボナッチ数、ナップサック問題、最短経路の数え上げなど）を高速に解けます。ダイクストラ法も「確定した最短距離を使って次を求める」という点で、動的計画法の考え方を使っています。

### 平衡2分探索木（AVL木）

2分探索木は、データを小さい順に挿入すると一方向に伸びた「片寄った木」になり、探索が線形探索と同じ O(n) まで遅くなります。**平衡2分探索木** は、挿入・削除のたびに木の形を調整して、高さを O(log n) に保つ木です。

- **AVL木**：どのノードでも、**左の部分木と右の部分木の高さの差が1以下** になるように保つ。差が2になったら **回転**（親子の付け替え）を行って調整する。
- 探索・挿入・削除の計算量はいずれも **O(log n)**。
- **B木**：1つのノードに多数のキーを持たせた平衡木。ディスクの読込み回数を減らせるので、データベースのインデックスに使われる。

### その他の頻出アルゴリズム

| アルゴリズム | 内容 |
|---|---|
| **エラトステネスの篩** | 2 から n までの数を並べ、小さい素数から順にその **倍数を消していく**。残った数が素数。√n までの数の倍数を消せば十分なので効率がよい |
| **ユークリッドの互除法** | 2つの整数の最大公約数を、「大きい方を小さい方で割った余り」で置き換えることを、余りが0になるまで繰り返して求める |
| **文字列照合（BM法など）** | 長い文字列の中から特定の文字列（パターン）を探す。BM法はパターンの末尾から比較し、不一致のときに大きくずらして高速化する |
| **多倍長整数の演算** | 桁数の非常に大きい整数を配列に分けて格納し、筆算と同じ要領で計算する。カラツバ法は掛け算の回数を減らして高速化する |
| **誤差拡散法** | 画像を白黒2値にするとき、各画素の丸め誤差を周りのまだ処理していない画素に分配して、全体の濃淡を保つ |

最大公約数 GCD(84, 36)：84 ÷ 36 ＝ 2 余り 12 → 36 ÷ 12 ＝ 3 余り 0 → 余りが0になったときの割る数 **12** が答え。
:::

## 9. 過去問（令和2〜6年度）で問われた発展テーマ

### ヒープを配列で表す

完全2分木は、配列に **上の段から順、同じ段は左から順** に格納できます。添字を1から始めると、

- 要素 A[i] の **左の子は A[2i]、右の子は A[2i＋1]**、親は A[i÷2]（小数点以下切捨て）

という計算で親子をたどれます。ポインタが不要なので、ヒープソートや優先度付きキューの実装に使われます。

### 2分探索木からの削除

2分探索木から要素を削除するときは、「左 ＜ 親 ＜ 右」のルールを崩さないように、次のように処理します。

- 削除する節に **子がない**：そのまま削除する。
- **子が1つ**：その子を削除した位置に繰り上げる。
- **子が2つ**：**左部分木の最大値**（または **右部分木の最小値**）を、削除した位置に移動する。

### ハッシュ値の計算

:::calc 除算法によるハッシュ
ハッシュ関数 h(x) ＝ x mod 7（7で割った余り）、ハッシュ表の位置は0〜6。キー 15, 22, 30 を格納する。
15 mod 7 ＝ **1**、22 mod 7 ＝ **1**、30 mod 7 ＝ **2**。15 と 22 は同じ位置1になり、**衝突（シノニム）** が発生します。オープンアドレス法なら、22 は次の空き位置（位置2…が埋まっていればさらに次）に格納します。
:::

### クイックソートのトレース

クイックソートは、**基準値（ピボット）** を選び、それより小さい値を左、大きい値を右に分けることを再帰的に繰り返します。

:::calc 先頭要素をピボットにした1回目の分割
[3, 5, 1, 4, 2] でピボットを先頭の 3 とする。
3 より小さい {1, 2} を左に、大きい {5, 4} を右に分ける → [1, 2] **3** [5, 4]
3 の位置が確定。次に [1, 2] と [5, 4] をそれぞれ同じ方法で整列します（分割統治法）。
:::

- **分割統治法**：大きな問題を、同じ形の小さな部分問題に分割して解き、その結果を組み合わせて全体の答えを得る設計手法。クイックソート、マージソートが代表例。

### 流れ図と決定表

- **流れ図（フローチャート）**：処理の流れを記号で表した図。ひし形が判断（分岐）、長方形が処理、台形が繰返しの始まりと終わり。
