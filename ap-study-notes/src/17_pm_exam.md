午後試験（2026年度からは「科目B試験」）は、1問あたり数ページの長文の事例（ある会社の状況説明）を読み、設問に **記号選択・穴埋め・数値計算・記述（20〜40字程度）** で答える形式です。「知識を覚えているか」よりも、「**事例の中で、知識をどう使うか**」が問われます。この章では、全分野に共通する解き方と、分野ごとの攻略の型をまとめます。具体的な演習は、今後作成する「午後対策シート」で行います。

## 1. 記述式問題の基本ルール

### 答えは「問題文の中」にある

午後問題の最大のコツは、**答えの根拠は、ほぼ必ず問題文の中にある** ということです。自分の経験や一般論で答えるのではなく、「問題文のどこに書いてある事実を使えば、この設問に答えられるか」を探します。

:::how 記述問題を解く5ステップ
**①設問を先に読む**：何が問われているか（理由？対策？名称？）、字数、条件（「〜の観点から」など）を確認する。
**②本文を読む**：設問に関係しそうな箇所（下線部、〔 〕の見出し、表や図）に印を付けながら読む。
**③根拠を探す**：下線部の前後、設問で指定された節を中心に、答えの根拠となる記述を見つける。
**④本文の言葉で書く**：根拠となる記述の **キーワードをそのまま使って** 答えを組み立てる。
**⑤問いに正対する**：「理由」を問われたら「〜ため」、「目的」なら「〜するため」、「問題点」なら「〜という問題がある」と、問いの形に合わせて文末を整える。
:::

### 記述のコツ

- **キーボード入力に慣れる**（CBT方式）：記述はキーボードで入力します。日本語入力の変換ミスや、字数の数え方に注意し、過去問を解くときもパソコンで入力して練習しておくと安心です。

- **字数の8割以上は書く**：30字以内なら24〜30字が目安。短すぎると要素が足りないことが多い。
- **1つの解答に1つの論点**：「AとBとCのため」のように欲張らず、問われている核心を書く。
- **主語と目的語をはっきり**：「漏えいするため」ではなく「**顧客情報が** 漏えいするため」。
- **問題文にない用語や数値を勝手に作らない**。
- **わからなくても空欄にしない**：部分点がもらえることがある。

:::point 「なぜ？」に強くなる練習
午後の記述は「なぜその対策が必要か」「なぜその方式では問題があるのか」を問うものが中心です。午前の学習のときから、用語を覚えるだけでなく「**それは何を防ぐ（実現する）ためのものか**」を一言で説明する練習をしておくと、午後で大きな力になります。
:::

## 2. 選択問題の選び方

### 選択の考え方

- 本番の前に、**得意分野を5〜6分野** 決めておき、それを重点的に練習する。本番では問題を見て、その中から解きやすそうな4問を選ぶ（その年の難易度によって入れ替えられるよう、少し多めに準備）。
- 選ぶ基準は「その分野の午前知識がしっかりあるか」と「過去問の得点が安定しているか」。

## 3. 分野別の解き方の型

### 問1 情報セキュリティ（必須）

:::how 情報セキュリティの解き方
**①攻撃の流れを把握する**：「何が・どこから・どうやって侵入し・何が起きたか」を図や時系列で整理する。
**②攻撃名と対策を結び付ける**：第9章の対応表（SQLインジェクション→プレースホルダ、など）を即答できるようにする。
**③構成図の機器と通信経路を確認する**：ファイアウォールのルール（送信元・宛先・ポート・許可/拒否）の穴埋めがよく出る。
**④「なぜ」を答える**：「この対策で何が防げるか」「この設定のままだと何が起きるか」を、本文の事実を使って書く。
:::

**頻出テーマ**：マルウェア感染と初動対応、ログの分析、ファイアウォールのルール設定、認証方式（多要素認証、パスワードの安全な保存＝ソルト＋ハッシュ）、Webアプリの脆弱性、メールのなりすまし対策（SPF・DKIM・DMARC）、TLSと証明書、ゼロトラスト、クラウドの設定ミス。

### 問2 経営戦略

:::how 経営戦略の解き方
**①会社の状況を分類する**：本文の事実を SWOT（内部の強み・弱み、外部の機会・脅威）に振り分けながら読む。
**②フレームワークの用語を正確に**：PPM の位置付け、BSC の視点、マーケティングの4P などを問われたら、用語の定義どおりに答える。
**③計算は落とさない**：損益分岐点、利益率、投資回収などの計算は、第16章の公式で確実に得点する。
**④施策の理由は「会社の課題」と結び付ける**：「売上が伸び悩んでいる」「若年層の顧客が少ない」など、本文に書かれた課題を解決する方向で答える。
:::

### 問3 プログラミング（アルゴリズム）

:::how プログラミングの解き方
**①プログラムの目的と変数の意味をつかむ**：問題文の説明と、プログラム中の変数名・コメントを対応させる。
**②小さな例でトレースする**：問題文の例（配列の値など）を使って、第2章のように変数の変化を表に書く。空欄は「この行の後でこの変数はこうなっているはず」から逆算する。
**③境界条件に注意**：ループの開始値・終了値（1からか0からか、n か n−1 か）、「＜」か「≦」かで答えが変わる。
**④計算量・実行回数の設問**：ループの入れ子と回数から考える。
:::

**頻出テーマ**：探索・整列、再帰、木構造・グラフ（最短経路）、文字列処理、2進数・ビット演算、動的計画法、スタック・キュー。

### 問4 システムアーキテクチャ

:::how システムアーキテクチャの解き方
**①構成図を読み解く**：サーバの台数・役割、冗長化の方式、データの流れを確認する。
**②計算問題**：稼働率（直列・並列）、処理能力（1秒あたりの処理件数）、必要台数、CPU使用率などを第3・4章の公式で解く。単位（ミリ秒・秒、件/秒）の換算に注意。
**③方式の比較**：スケールアップとスケールアウト、ホットスタンバイとコールドスタンバイ、クラウドの利用形態の長所・短所を、本文の要件（コスト・可用性・性能）に照らして答える。
:::

### 問5 ネットワーク

:::how ネットワークの解き方
**①構成図に情報を書き込む**：各機器の IPアドレス、サブネット、VLAN、通信経路を図に書き込みながら読む。
**②パケットの流れを追う**：「PC → スイッチ → ルータ → ファイアウォール → サーバ」と、通信がどの機器を通り、どこで何が変換されるか（NAT など）を追う。
**③プロトコルの役割を答える**：DNS（名前解決）、DHCP（アドレス割当て）、ARP（MACアドレスの解決）などを、本文の場面に当てはめる。
:::

**頻出テーマ**：サブネットの計算、ルーティングテーブル、DNS の設定、冗長化（VRRP、リンクアグリゲーション）、無線LAN、VPN、プロキシ、負荷分散。

### 問6 データベース

:::how データベースの解き方
**①E-R図と表の定義を対応させる**：エンティティ、主キー（実線の下線）、外部キー（破線の下線）、多重度（1対多など）を確認する。
**②E-R図の空欄**：「1つの〇〇に対して複数の△△があるか」を本文の業務ルールから読み取り、リレーションシップの線を補う。
**③SQL の穴埋め**：SELECT・FROM・WHERE・GROUP BY・HAVING の役割（第7章）を思い出し、「何を数えるのか（COUNT）」「どの単位でまとめるのか（GROUP BY）」「結合条件は何か」を考える。
**④正規化・更新時異状**：「どの関数従属が問題か」「どの表に分けるべきか」を答える。
:::

### 問7 組込みシステム開発

:::how 組込みシステムの解き方
**①ハードウェア構成と動作の流れをつかむ**：センサー → 制御部（CPU）→ アクチュエータの流れと、各タスクの役割を整理する。
**②状態遷移表・タイミングチャートを丁寧に読む**：「どのイベントで、どの状態からどの状態に移るか」を表で確認する。
**③計算問題**：割込みの周期、タイマのカウント値、バッテリーの持続時間、データ量などを、単位に注意して計算する（第3章の計算例を参照）。
**④タスク間の制御**：排他制御（セマフォ）、優先度、イベントフラグなど、第5章の知識を使う。
:::

### 問8 情報システム開発

:::how 情報システム開発の解き方
**①設計図（クラス図・シーケンス図・状態遷移図）を読み解く**：第10章の UML の意味を確認しながら、本文の業務と対応させる。
**②テストの設問**：テストケースの設計（同値分割・限界値分析）や、どのテストで確認すべきかを答える。
**③開発手法の設問**：アジャイル・スクラム・CI/CD の考え方と、その事例での利点・注意点を答える。
:::

### 問9 プロジェクトマネジメント

:::how プロジェクトマネジメントの解き方
**①プロジェクトの状況と課題を整理する**：目標（納期・予算・品質）、制約、ステークホルダー、発生している問題を書き出す。
**②計算は確実に**：工数（人月）、要員数、EVM、クリティカルパスの計算は第11章の公式で解く。
**③対応策は「PMの立場」で**：プロジェクトマネージャとして、リスクを早期に見つけ、関係者と合意を取り、計画を見直す、という行動を本文の事実に即して書く。
**④「なぜその対応をとったのか」を問われたら**：本文中の懸念点（「〜の可能性がある」「〜が不慣れ」など）とセットで答える。
:::

### 問10 サービスマネジメント

:::how サービスマネジメントの解き方
**①サービスの内容と SLA を確認する**：サービス時間、稼働率の目標、問合せの対応時間など。
**②プロセスを正しく区別する**：インシデント管理（迅速な回復）と問題管理（根本原因の解決）、変更管理とリリース管理（第12章）。
**③計算問題**：稼働率、許容停止時間、対応件数、要員数などを計算する。
**④改善策は「再発防止」と「影響の最小化」の観点で**：本文の障害の経緯から、どこを改善すべきかを読み取る。
:::

### 問11 システム監査

:::how システム監査の解き方
**①監査の目的（監査要点）を確認する**：「何が適切かどうか」を確かめる監査なのかを把握する。
**②リスクを見つける**：本文の業務の流れの中で、「職務分掌ができていない」「承認の記録がない」「定期的な見直しがされていない」などの弱点（リスク）を探す。
**③監査手続・監査証拠を答える**：「〇〇の記録を確認して、△△が行われているかを確かめる」という形で、**確認する証拠（記録・文書）** と **確認する内容** をセットで書く。
**④監査人の立場を守る**：監査人は改善を「実施」しない。「確認する」「評価する」「指摘する」という表現で答える。
:::

## 4. 過去問演習の進め方

1. **まず午前知識を固める**：本書の第1〜16章を読み、午前の過去問で6割以上取れるようにする。午後の土台は午前の知識です。
2. **時間を気にせず1問解く**：最初は分野ごとに、時間無制限で1問をじっくり解く。
3. **解答例と採点講評を読む**：IPA が公開している **解答例** と **採点講評** を読み、「どの本文の記述を根拠にしているか」を確認する。採点講評には、受験者が間違えやすかった点が書かれています。
4. **同じ分野を3〜5年分解く**：出題パターンや頻出テーマに慣れる。
5. **時間を計って解く**：本番を想定して、1問25〜30分で解く練習をする。

:::exam 令和7年度の午後問題
令和7年度（2025年度）の春期・秋期も、問1 情報セキュリティ（必須）と、問2〜問11 の10分野から4問選択という構成でした。IPA のサイトでは、問題冊子・解答例・採点講評が公開されているので、最新年度から順に解いていくことをおすすめします。
:::
